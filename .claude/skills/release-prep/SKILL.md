# 릴리스 준비

AgentHub 릴리스(`npm run release`)를 돌리기 전에 저장소를 준비한다. **릴리스 자체는 직접 실행하지 않는다.** 실제 릴리스는 흐름의 명령 노드가 사람의 승인을 받은 뒤 실행한다.

## 순서
1. `git status`와 `git log --oneline`으로 지난 릴리스(`chore: release vX.Y.Z`) 이후 바뀐 내용을 파악한다.
2. 버전 단위를 판단해 답변에 적는다. 기본은 patch, 새 기능이 크면 minor, 호환이 깨지면 major.
   - patch가 아니면 "릴리스 명령을 `npm run release -- minor`로 바꿔야 한다"고 분명히 알린다.
3. README처럼 기능을 설명하는 문서가 바뀐 기능과 어긋나면 고친다.
4. `npm test`로 테스트가 통과하는지 먼저 확인한다. 실패하면 고친다.
5. 변경을 커밋한다. 커밋 메시지는 이 저장소 형식을 따른다(예: `feat: …`, `fix: …`, 한국어 요약).
   - 커밋하지 않은 변경이 남으면 릴리스 스크립트가 멈추므로 `git status`가 깨끗해야 한다.
   - `dist/`, `node_modules/` 같은 빌드 결과는 커밋하지 않는다.
6. 하지 않는 것: `npm run release`, `npm version`, `git push`, `git tag`, `gh release`.
7. 모두 끝났으면 바뀐 점 요약과 추천 버전 단위를 쓰고, **마지막 줄에 정확히 "릴리스 준비"**라고 쓴다. 준비가 안 됐으면 이 말을 쓰지 않는다.

## 릴리스가 실패해서 돌아왔을 때
- 출력을 보고 원인을 진단해 보고한다. 직접 다시 릴리스하지 않는다.
- 버전만 올라가고 커밋이 안 된 상태(`package.json` 변경)인지, 커밋·태그까지 된 상태인지 확인해 알린다.
