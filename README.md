# AgentHub

Claude Code와 Codex 세션을 한 화면에서 만들고 이어 가는 데스크톱 앱(Electron)이다. 브라우저로 여는 로컬 웹앱으로도 쓸 수 있다. 각 에이전트의 CLI를 대신 실행하므로, 이미 로그인한 구독 계정의 사용량 안에서 동작한다. API 키를 쓰지 않는다.

## 요구 사항

- git
- Claude Code CLI: 로그인되어 있어야 한다(`claude auth login`). PATH에 없으면 Claude 데스크톱 앱이 내려받은 `claude.exe`를 자동으로 찾는다.
- Codex CLI: 로그인되어 있어야 한다(`codex login`). `npm i -g @openai/codex`로 설치한 경우 `%APPDATA%\npm`에서 자동으로 찾는다.
- 소스에서 실행하거나 빌드할 때는 Node.js 20 이상

CLI가 없거나 로그인이 안 됐으면 앱 안에서 설치·로그인할 수 있다. 사이드바의 CLI 상태에 뜨는 **설치**·**로그인** 버튼이나 **설정 → CLI 경로 → 설치·로그인**에서 Claude Code·Codex·GitHub CLI를 다룬다.

- 설치는 winget으로 한다. winget이 없으면 Claude Code는 공식 설치 스크립트(`install.ps1`), Codex는 npm으로 설치한다.
- 로그인은 각 CLI의 브라우저 로그인을 실행하고, 출력에서 로그인 주소와 일회용 코드를 꺼내 창에 보여 준다. Claude가 코드를 붙여 넣으라고 하면 창에서 입력한다.
- 진행 출력이 실시간으로 보이고, 끝나면 CLI 경로·버전·로그인 상태를 다시 확인한다. **다시 확인**은 최신 PATH와 실행·로그인 상태를 새로 읽는다. 찾은 실행 파일 경로와 실행 실패·로그인 필요를 구분해 표시하며, 자동으로 찾지 못하면 설정에서 실행 파일을 직접 지정할 수 있다.

서버는 외부 패키지를 쓰지 않는다. Electron과 electron-builder는 앱 실행·빌드용 개발 의존성이다.

## 실행

### 데스크톱 앱

[Releases](https://github.com/Lyeol2/AgentHub/releases)나 `dist/`의 `AgentHub-Setup-<버전>.exe`(설치형)나 `AgentHub-<버전>-portable.exe`(설치 없이 실행)를 쓴다. 앱이 서버를 내부에서 띄우고 창을 연다. 창을 닫으면 실행 중인 에이전트를 멈추고 세션을 저장한 뒤 종료한다.

설치본의 세션 기록과 설정은 `%APPDATA%\AgentHub\data`에 저장된다.

```bash
npm install
npm run app
```

`npm run app`은 소스에서 바로 앱을 띄운다. 이때는 저장소의 `data/`를 쓴다. 설치 파일은 `npm run dist`로 만든다.

### 업데이트

설치형 앱은 시작 5초 뒤, 이후 1시간마다, 그리고 사이드바 아래 **업데이트 확인** 버튼을 누를 때 GitHub Releases의 최신 버전을 확인한다. 새 버전이 있으면 백그라운드에서 바로 받고, **재시작해서 업데이트**를 누르면 설치 창 없이 설치한 뒤 앱을 다시 실행한다. 받아 둔 업데이트는 앱을 닫을 때도 조용히 설치된다.

저장소가 공개라서 GitHub 로그인 없이 누구나 업데이트를 받는다. 0.1.12 이하는 비공개 저장소용으로 `gh auth login`이 필요했으므로, `gh`가 없는 PC는 0.1.13 이후 설치 파일을 한 번 직접 설치해야 한다. 포터블 버전은 자기 자신을 바꿀 수 없어서 릴리스 페이지를 연다.

### 릴리스

```bash
npm run release
```

테스트, 버전 올리기, 빌드, 커밋·태그 push, GitHub Release 생성까지 한 번에 한다. 버전 단위는 release-prep이 준비한 값을 자동으로 쓰고, 준비한 값이 없으면 patch로 올린다. `npm run release -- minor`처럼 직접 지정하면 그 값이 우선한다. 앱의 업데이트 기능은 릴리스에 함께 올라가는 `latest.yml`을 읽는다. 마지막 커밋을 임시 작업 트리에 꺼내 빌드하므로 커밋하지 않은 변경은 릴리스에 들어가지 않고 그대로 남는다. 단, `package.json`·`package-lock.json`에 커밋하지 않은 변경이 있으면 시작하지 않는다.

- 릴리스 노트는 지난 태그 이후 커밋으로 만든다. `feat:`·`fix:`·`chore:` 같은 앞머리로 종류를 묶고, 커밋 본문의 `- ` 줄을 아래에 붙인다(릴리스 커밋은 뺀다).
- 릴리스 준비 단계(release-prep 스킬)가 점검을 통과하면 커밋 노트를 사용자 말투로 다시 쓴 초안을 `release-notes.draft.md`(git 제외)에 남기고, 첫 줄에 기준 커밋과 버전 단위(`bump=patch|minor|major`)를 기록한다. 큰 기능 추가나 주요 사용 흐름 변경은 minor로 자동 선택한다. 승인 전에 고칠 수 있고, 릴리스할 때 이 초안이 커밋 노트 대신 나간 뒤 지워진다. 초안을 쓴 뒤 커밋이 더 생겼으면 버전 단위와 노트를 모두 쓰지 않고 기본 patch·커밋 노트로 진행하므로, 다시 준비해야 한다.
- 릴리스가 끝나면 같은 노트를 **Discord 웹후크**로 보낸다. 주소는 비밀이라 저장소에 두지 않고, 환경 변수 `AGENTHUB_DISCORD_WEBHOOK`이나 저장소 루트의 `release.local.json`(git 제외)에 `{ "discordWebhook": "https://discord.com/api/webhooks/..." }`로 적는다. 없거나 보내지 못해도 릴리스는 그대로 끝난다.
- `node scripts/release-notes.mjs`는 다음 릴리스에 들어갈 노트를 미리 보여 주고, `node scripts/release-notes.mjs v0.1.15 --discord`는 그 버전의 노트를 Discord로 다시 보낸다.

### 브라우저

```bash
npm start
```

브라우저에서 <http://127.0.0.1:4517>을 연다. 포트는 `PORT` 환경 변수나 `data/config.json`의 `port`로 바꾼다. 같은 포트를 쓰므로 데스크톱 앱과 동시에 띄우지 않는다.

아이콘은 `build/make-icon.ps1`이 그린다. 고친 뒤 `powershell -ExecutionPolicy Bypass -File build/make-icon.ps1`로 `build/icon.ico`를 다시 만든다.

### 사용법

1. 대시보드에 Claude Code·Codex로 작업한 프로젝트가 자동으로 올라온다. 기록이 없는 폴더는 **설정**에서 직접 추가한다.
2. **새 세션**에서 에이전트, 프로젝트, 권한을 고른다. 기본은 프로젝트 원본 폴더다. 별도로 작업하려면 **워크트리에서 작업하기**를 켜고 이름을 직접 입력한다.
3. 요청을 보내면 CLI 출력이 실시간으로 표시된다. 다음 요청은 같은 CLI 세션을 이어서 실행한다.

### 이미지 첨부와 기록 내보내기

- 세션과 일반 채팅의 입력창에서 **이미지 첨부**를 누르거나, 이미지를 붙여넣거나 끌어 놓는다. PNG·JPEG·GIF·WebP를 요청당 4장, 파일당 10MB까지 첨부할 수 있다. 미리보기에서 뺄 수 있고 글 없이 이미지만 보낼 수도 있다.
- 첨부 이미지는 Claude에는 이미지 콘텐츠로, Codex에는 로컬 이미지 입력으로 전달한다. 실행 중에는 선택한 방식에 따라 지금 작업에 붙이거나 이미지와 함께 대기열에 넣는다. 업로드나 전송이 실패하면 초안을 보존하고 재시도할 수 있다.
- 프로젝트 세션의 **기록 내보내기**를 누르면 현재까지의 요청·답변·도구 출력·질문과 권한 결정 기록을 Markdown으로 저장한다. 저장 위치는 화면에 표시하며, 세션 작업 폴더의 `docs/agenthub/` 아래에 새 파일을 만든다. 워크트리 세션은 해당 워크트리 안에 저장한다.
- 기록에 포함된 이미지도 문서 옆에 복사해 상대 경로로 연결한다. 기존 문서는 덮어쓰지 않으며 일반 채팅은 프로젝트 문서 내보내기를 제공하지 않는다.

### AGENTHUB.md

프로젝트 루트의 `AGENTHUB.md`에는 세션끼리 협업하는 방식만 적는다. 코드 규칙·빌드 명령 같은 프로젝트 지식은 각 CLI가 알아서 읽는 `CLAUDE.md`·`AGENTS.md`에 둔다. 프로젝트 화면의 **AGENTHUB.md 만들기**로 예시 파일을 만들 수 있다.

```markdown
## 공통 지침
모든 세션의 첫 요청에 붙는다.

## 역할: 리뷰
- 에이전트: codex
- 권한: read-only
- 작업 폴더: 원본

코드를 고치지 않는다. 답변의 마지막 줄에는 판정 하나만 쓴다. 고칠 것이 있으면 "수정 필요", 없으면 "통과".

## 흐름: 구현과 리뷰
- 구현 -> 리뷰: "검토 요청"
- 리뷰 -> 구현: "수정 필요" | 리뷰에서 지적한 것만 고친다.
```

- 역할의 설정 줄(에이전트, 권한, 모델, 작업 폴더)은 생략하면 claude · acceptEdits · 원본을 쓴다. 설정 줄 다음부터가 역할 본문이다.
- 흐름의 조건은 `성공`, `실패`, `항상`, `그 외`, `수동`이고 그 밖의 말은 키워드다(조건 이름을 키워드로 쓰려면 따옴표로 감싼다. 여러 키워드는 쉼표로 나눈다). 생략하면 성공이고, `|` 뒤는 받는 세션에 줄 지시다.
- **새 세션**에서 역할 템플릿을 고르면 에이전트·권한·역할이 채워진다. 작업 폴더는 자동으로 분리하지 않으며, 워크트리를 쓰려면 직접 선택하고 이름을 입력한다. **흐름 시작**은 원본 폴더를 쓰는 세션을 역할마다 만들고 연결한 뒤, 첫 요청을 받는 연결이 없는 역할에 보낸다.
- 파일은 쓸 때마다 다시 읽는다. 형식이 틀린 줄은 프로젝트 화면에 경고로 보인다.

### 오케스트레이터

프로젝트 화면의 **오케스트레이터 만들기**(또는 새 세션에서 **오케스트레이터 세션** 선택)로 지휘 세션을 만든다. 오케스트레이터는 선택한 작업 폴더에서 읽기만 한다(Claude는 `default` 권한: 수정·명령은 거절된다, Codex는 `read-only`).

1. 오케스트레이터에 목표를 보낸다. 첫 요청에는 지휘 규칙, `AGENTHUB.md`의 역할 템플릿, 이 프로젝트의 세션 목록이 붙고, 이후 요청에는 세션 상태가 붙는다.
2. 오케스트레이터가 답변 끝에 ` ```agenthub-plan ` JSON 블록으로 계획(만들 세션, 연결, 보낼 요청)을 쓰면 세션 화면에 계획 카드가 뜬다.
3. **승인하고 실행**하면 세션을 만들고 연결한 뒤 요청을 보낸다. **거절**에 이유를 적으면 오케스트레이터가 계획을 고친다. 형식이 틀린 계획은 실행하지 않고 오류를 보여 준다.
4. 계획에 워커 → `orchestrator` 연결을 넣으면 결과가 오케스트레이터로 돌아오고, 오케스트레이터가 다음 계획을 세우거나 끝났다고 보고한다.

계획은 매번 사람이 승인해야 실행된다. 새 세션은 원본 폴더가 기본이며, 계획에 `isolate: true`와 `worktreeName`을 명시한 경우에만 워크트리를 만든다. 승인 카드에서 작업 폴더와 이름을 확인할 수 있다. 한 계획에서 새 세션은 8개까지 만들 수 있고, 그래프에는 오케스트레이터가 만든 세션으로 점선 지휘선이 그려진다.

### 역할과 세션 연결

세션마다 **역할**(맡는 일, 고쳐도 되는 범위, 건드리면 안 되는 범위)을 적어 두면 새 대화의 첫 요청에 붙여 보낸다. 대화 중에 바꾸면 다음 요청에 바뀐 역할을 함께 보낸다.

프로젝트 화면의 **세션 흐름**에 세션이 카드로 나온다. 카드를 한 번 누르면 고르기만 하고, 두 번 누르면 연다(Ctrl·Shift+두 번 누르기는 새 창). Ctrl·Shift를 누르고 누르면 선택에 더하거나 빼고, 빈 곳을 끌면 선택 상자로 여러 카드를 고른다. **Delete**를 누르면 선택한 세션·명령을 한 번의 확인으로 함께 삭제한다. 작업 폴더와 CLI 원본 기록은 유지한다. 카드를 끌면 위치가 저장되고, 고른 카드를 끌면 함께 옮겨진다. Esc는 선택을 푼다.

마우스 휠을 돌리면 커서 위치를 기준으로 확대·축소하고, **휠 버튼을 누른 채 끌면 화면을 이동**한다. 그래프 위의 −·+ 버튼으로도 배율을 바꿀 수 있고, 배율 표시를 누르면 100%로, **맞춤**은 모든 카드가 보이게 맞춘다. 배율은 프로젝트마다 기억한다. 카드 오른쪽 ● 손잡이를 다른 카드로 끌면 연결 설정이 열린다. **빈 곳에 놓으면 새 세션·새 명령 메뉴**가 열리고, 만든 노드에 바로 연결된다.

왼쪽 사이드바와 오른쪽 화면 사이의 경계를 끌면 너비가 바뀌고 이 브라우저에 저장된다. 경계를 두 번 누르면 기본 너비로 돌아간다. 키보드로 경계를 선택한 뒤 좌우 방향키로 조절할 수도 있다.

- 답변 마지막 줄에 키워드가 있으면 / 턴이 성공하면 / 턴이 실패하면 / 다른 연결이 모두 안 맞으면(그 외) / 턴이 끝날 때마다 / 수동으로만
- 한 세션에서 나가는 연결은 if/else처럼 고른다. 키워드가 맞은 연결이 있으면 그것만, 없으면 성공·실패 연결, 그것도 없으면 그 외 연결을 따라간다. 턴이 끝날 때마다 연결은 언제나 함께 넘긴다. 아무 연결도 맞지 않으면 세션 기록에 이유를 남긴다.
- 키워드는 답변의 마지막 줄에서만 찾는다. 키워드 바로 뒤에 부정이 붙으면("수정 필요 없음") 맞지 않은 것으로 본다. 연결 대화상자는 보내는 세션의 역할에서 "마지막 줄"·"판정"을 말하는 줄의 따옴표 말을 키워드 후보로 보여 주고, 새 연결이면 아직 쓰지 않은 후보를 미리 고른다.
- 조건이 맞으면 보낸 세션의 마지막 답변, 기준 커밋 이후 바뀐 파일 목록, 작업 폴더 경로를 받는 세션의 요청으로 보낸다. 지시 문구를 따로 적을 수 있다.
- 받는 세션이 실행 중이면 끝난 뒤 시작한다. 사용자가 중지한 턴은 넘기지 않고, 그 세션에 밀린 작업도 버린다.
- 서로를 가리키는 연결이 끝없이 돌지 않게, 자동으로 이어지는 흐름은 8단계까지만 간다. 사용자가 직접 보낸 요청에서 다시 1단계로 센다(흐름 중간에 에이전트가 물은 질문에 답한 것은 같은 흐름으로 이어 센다).

연결은 `data/links.json`에 저장된다. 세션을 지우면 그 세션의 연결도 지운다.

### 세션의 AI 바꾸기

세션 화면의 **설정**에서 AI(Claude ↔ Codex)를 바꿀 수 있다. 실행 중이 아닐 때만 바꿀 수 있다.

- CLI가 다르므로 CLI 대화는 새로 시작한다. 작업 폴더·브랜치·역할·연결·스킬·화면 기록은 그대로 둔다.
- **진행 상황 이어받기**(기본으로 켜짐)는 지금까지의 요청·답변·도구 사용·오류·주고받은 메시지와 바뀐 파일 목록을 정리해 새 AI의 첫 요청 앞에 붙인다. 길면 첫 요청은 남기고 가운데 기록부터 줄인다. 새 대화가 시작되면 넘긴 기록은 지운다.
- 모델은 AI마다 이름이 달라 비우고(CLI 기본값), 권한은 비슷한 것으로 옮긴다(Claude `plan` ↔ Codex `read-only`, `acceptEdits`·`bypassPermissions` ↔ `workspace-write`).
- 같은 AI 안에서 모델·추론 강도·권한만 바꾸면 대화는 그대로 이어진다.

### 일시중지·재개와 도구 호출 보기

세션 창 제목 옆과 흐름 노드 하단에는 현재 작업의 경과 시간이 `⏱ 3분 12초`처럼 표시되고 1초마다 갱신된다. 명령 노드에도 실행 시간이 보인다. 로그가 추가되거나 화면을 다시 열어도 같은 시작 시각을 쓰며, 완료·일시중지하면 실행 시간 표시를 끝내고 다음 실행부터 새로 센다.

요청창 옆의 버튼 하나로 전송·일시중지·재개를 한다. 요청을 입력하면 **↑ 보내기**, 실행 중에 입력하면 **대기열에 추가**로 바뀐다. 입력이 비어 있으면 실행 중에는 **⏸ 일시중지**, 멈춘 상태에서는 **▶ 재개**가 된다. 일반 채팅에서도 같은 방식으로 동작한다. Enter는 입력한 요청만 보내며, 빈 Enter는 작업을 멈추거나 재개하지 않는다.

**⏸ 일시중지**(또는 실행 중에 Esc)는 Claude Code·Codex에서 Esc를 누른 것처럼 턴을 멈추되 CLI 대화는 그대로 둔다. **▶ 재개**하면 같은 대화로 멈춘 곳부터 이어서 진행한다.

- Claude는 CLI에 interrupt 요청을 보내 턴을 정상으로 끝내고, Codex는 실행을 멈춘 뒤 다음 턴에 같은 스레드로 이어 간다.
- 일시중지한 동안 연결로 넘어오는 작업과 다른 세션의 메시지는 대기열에 쌓이고, 재개하면 차례로 보낸다.
- 일시중지 중에 요청을 직접 보내면 재개한 것으로 보고, 앞의 작업이 중간에 멈췄다는 것을 CLI에 함께 알린다.
- **중지**는 이어서 하지 않고 넘어온 작업도 버린다(사용자가 대기열에 넣은 요청은 남긴다).

도구 호출(명령 실행, 파일 읽기·수정, MCP 도구)은 한 줄로 접혀 보이고, 누르면 입력과 출력이 펼쳐진다. 턴이 도는 동안 결과가 아직 없는 호출에는 "실행 중…"이 붙는다. 머리의 **도구 펼치기**를 켜면 모두 펼쳐 둔다(이 브라우저에 기억한다).

### 세션끼리 소통

연결이 정해진 순서로 결과를 넘기는 것이라면, 메시지는 에이전트가 필요할 때 스스로 다른 세션에 말을 거는 통로다. 모든 세션(일반 채팅 제외)의 CLI에 AgentHub MCP 서버가 붙고, 첫 요청에 사용법이 붙는다.

| 도구 | 하는 일 |
| --- | --- |
| `list_sessions` | 같은 프로젝트에서 활성 노드 연결로 직접 연결된 세션(이름, 역할, 상태)만 본다. |
| `send_message(to, text)` | 다른 세션에 메시지를 보낸다. 받는 쪽이 실행 중이고 요청을 붙일 수 있으면(Claude, Codex) 작업 중인 턴에 바로 들어가고, 아니면 대기열을 거쳐 다음 요청으로 받는다. |
| `ask_session(to, question)` | 묻고 답이 올 때까지 기다린다(기본 5분, 최대 10분). 상대가 `send_message`로 답하면 도구 결과로 돌아온다. |
| `check_messages` | 작업 중에 와서 대기열에 쌓인 메시지를 꺼내 읽는다(Codex가 턴을 준비하는 중이라 바로 붙이지 못한 경우처럼 실행 중 턴에 들어가지 못한 메시지용). |
| `board_read` / `board_post(text)` | 프로젝트 **공유 노트**를 읽고 덧붙인다. 프로젝트 화면의 **공유 노트**에서 보고 고칠 수 있다. |

- 메시지와 질문은 활성화된 노드 연결로 직접 연결된 세션끼리만 보낼 수 있다. 답장을 위해 연결 방향은 구분하지 않는다. 꺼진 연결이나 다른 노드를 경유한 간접 연결은 허용하지 않는다. 대기 중 연결이 끊긴 메시지도 전달하지 않는다.
- 세션 연락은 직접 확인할 수 없는 정보·결정이 필요하거나, 실제 작업 충돌을 조율하거나, 요청받은 결과를 돌려줄 때만 한다. 확인·감사 답장, 요청받지 않은 일반 진행·완료 보고, 연결과 메시지의 중복 전달은 생략한다.
- `to`에는 세션 이름, 역할 이름, 세션 id를 쓴다. "작업 · 리뷰"처럼 흐름 이름이 붙은 제목은 "리뷰"만 써도 된다.
- MCP 도구를 쓸 수 없으면 답변 끝의 ` ```agenthub-message ` 블록(`{"to", "text", "wait"}`)으로 보낸다. `wait`이면 답이 올 때까지 그 세션의 연결로 넘기지 않고, 답을 받은 턴이 끝나면 연결로 넘긴다.
- 다른 세션의 메시지로 시작한 턴은 곁가지 대화로 보고 연결로 넘기지 않는다.
- 메시지로 새 턴을 여는 것도 자동 연결의 8단계 제한에 들어가고, 한 턴에 보낼 수 있는 메시지는 12개다. 서로의 답을 기다리는 `ask_session`은 거절한다.
- 주고받은 메시지는 세션 기록에 남고, 그래프에는 점선 대화선으로 보인다(마우스를 올리면 마지막 메시지). 최근 300개가 `data/messages.json`에, 공유 노트는 `data/boards/`에 저장된다.

### 스킬

스킬은 `<이름>/SKILL.md`(Claude Code·Codex 공통 형식)로 저장한다. 프로젝트 화면의 **스킬** 버튼이나 그래프 빈 곳 우클릭 → **스킬 관리**에서 만들고 고치고 옮긴다. 세션 카드의 스킬 칩을 누르면 그 세션에 스킬을 장착하고, 장착한 세션에는 새 대화의 첫 요청과 장착이 바뀐 직후 요청에 "이 작업을 할 때 이 스킬을 따르라"는 안내를 붙인다.

| 범위 | 위치 | 쓰는 세션 |
| --- | --- | --- |
| 프로젝트 (새 스킬 기본) | `<프로젝트>/.agenthub/skills` | AgentHub에서 장착한 세션만 |
| Claude 프로젝트 | `<프로젝트>/.claude/skills` | Claude가 그 프로젝트에서 저절로 쓴다. 예전 버전이 만들던 곳이라 새로 만들지 않고, 다른 범위로 옮길 수 있다. |
| 개인 | `~/.claude/skills`와 `~/.agents/skills` 두 곳에 같은 내용 | Claude·Codex가 모든 프로젝트에서 저절로 찾는다. |

- 이름이 겹치면 프로젝트 → Claude 프로젝트 → 개인 순으로 앞의 것을 쓴다.
- 개인 스킬이 두 곳에 다른 내용으로 있으면 AgentHub에서 고치거나 옮기지 않는다.
- 스킬을 지우거나 옮겨서 세션이 더는 찾을 수 없게 되면 그 세션의 장착도 뺀다.

### 프로젝트 화면의 탭

프로젝트 화면은 **세션 흐름**(그래프) · **세션 목록** · **Git** 탭으로 나뉜다. 마지막에 본 탭을 기억한다.

- **세션 목록**: 이 프로젝트의 AgentHub 세션을 표로 본다(AI·모델, 역할, 작업 폴더 브랜치, 상태). 제목·역할로 검색하고, 누르면 열고, 우클릭하면 세션 메뉴가 나온다. 아래에 Claude Code·Codex 기록 가져오기 목록이 있다.
- **Git**: **변경사항**·**History**·**Pull Requests**를 별도 탭으로 보여 주고 마지막에 본 탭을 기억한다.
  - **변경사항**: 스테이징 전·후 파일 목록에서 파일별, 선택한 파일, 표시된 파일 전체를 스테이징하거나 해제한다. 파일을 누르면 그쪽의 diff를 보여 준다. 일부만 스테이징된 파일은 두 목록에 각각 표시한다. 메시지를 적고 커밋하면 스테이징된 내용만 담고, 이후 수정한 내용은 작업 폴더에 남긴다.
  - **History**: 전체 로컬 브랜치의 최근 100개 커밋을 노선도로 보여 준다. 색 선은 분기·병합, 점선은 세션의 작업 중 상태와 커밋 전 변경이다. 세션 브랜치는 세션 이름으로 표시한다. 커밋을 누르면 아래에 변경 내용이 열린다. 현재 작업 노드를 누르면 변경사항 탭으로 이동한다.
  - **Pull Requests**: GitHub 원격 저장소의 열린 PR·닫힌 PR·병합된 PR 목록, 설명·검사 상태·파일·diff를 본다. 현재 브랜치로 PR 또는 초안을 만들고, 필요한 브랜치 게시는 별도 버튼으로 한다. PR 병합(Merge/Squash/Rebase)과 닫기는 내용을 확인한 뒤 실행한다. GitHub CLI 설치·로그인이 필요하며, 화면의 안내에서 기존 설치·로그인 창으로 이동할 수 있다.
  - 기본 세션은 프로젝트 원본 폴더에서 작업하므로 고친 파일이 변경사항 탭에 바로 보인다. 워크트리를 선택한 세션의 변경은 해당 작업 폴더와 브랜치에 남는다. 확인한 뒤 스테이징하고 커밋한다.
  - 현재 브랜치보다 앞선 커밋이 있는 브랜치는 차이를 보고 현재 브랜치로 병합할 수 있다. 이전 버전에서 분리한 세션의 브랜치도 이렇게 가져온다.
  - 병합은 `--no-ff`로 하고, 충돌이 나면 되돌린 뒤 충돌한 파일을 알린다.
  - PR 만들기에 필요한 현재 브랜치 게시는 지원한다. 강제 push·pull·fetch, 포크 간 PR 생성은 지원하지 않는다. PR 원격 작업은 GitHub에 적용되며 로컬 브랜치를 자동으로 바꾸거나 병합하지 않는다.
  - 세션 시작·종료, 다른 창의 스테이징·커밋·병합, 창으로 돌아왔을 때 다시 읽는다.

### 프로젝트 자동 감지와 기존 세션 가져오기

Claude Code·Codex 기록에 남은 작업 폴더를 모아 프로젝트 목록을 만든다. 작업 폴더는 git 저장소 루트로 묶고, AgentHub 작업 폴더(`<저장소>.agenthub/...`)와 Claude Code 작업 트리(`<저장소>/.claude/worktrees/...`)는 원래 저장소로 합친다. 임시 폴더, 홈 폴더, 지금은 없는 폴더는 뺀다. 첫 검색은 기록 양에 따라 1~2초 걸리고, 이후에는 바뀐 파일만 다시 읽는다.

프로젝트를 누르면 **Claude Code · Codex 세션**에 Claude Code·Codex 앱이나 CLI에서 그 프로젝트로 연 세션이 나온다. 감지만 된 프로젝트는 세션을 가져오거나 새로 만들 때 AgentHub 프로젝트로 등록된다. **가져오기**를 누르면 대화 기록(최근 400개 항목)을 보여 주고, 다음 요청부터 그 CLI 세션을 `--resume`으로 이어서 실행한다.

- Claude: `~/.claude/projects/<인코딩된 경로>/*.jsonl`
- Codex: `~/.codex/sessions/**/rollout-*.jsonl` (하위 에이전트·검토용 스레드는 제외)

원래 기록 파일은 읽기만 한다. 같은 세션을 다른 앱에서 동시에 이어 쓰면 기록이 엇갈릴 수 있다.

**프로젝트 제거**(프로젝트 화면 위, 또는 사이드바 프로젝트 우클릭)는 AgentHub 목록에서 프로젝트를 뺀다.

- 이 프로젝트의 AgentHub 세션·명령 노드·연결·공유 노트·메시지 기록을 지운다. 지운 세션의 CLI 기록은 가져오기 목록에서 숨긴다.
- 프로젝트 폴더와 파일, `AGENTHUB.md`, 스킬 파일, Claude Code·Codex의 기록 파일은 건드리지 않는다.
- 워크트리를 선택한 세션의 작업 폴더는 기본으로 남기고, 제거 창에서 **분리한 작업 폴더도 지우기**를 고르면 함께 지운다(커밋하지 않은 변경이 있으면 남기고 알린다). 브랜치는 지우지 않는다.
- 이전 버전에서 원본으로 전환된 세션의 작업 폴더(`<저장소>.agenthub/...`)와 `agenthub/...` 브랜치는 지우지 않는다. 필요 없으면 `git worktree remove`·`git branch -d`로 직접 지운다.
- 실행 중인 세션이 있으면 멈추고 제거할지 묻는다.
- 제거한 프로젝트는 기록에서 다시 감지돼도 목록에 보이지 않는다. 같은 폴더를 다시 추가하거나 거기서 세션을 만들면 다시 보인다.

### 사용 한도

대시보드의 **사용 한도**와 사이드바 아래에 남은 비율과 초기화 시각이 나온다. 사이드바에는 에이전트마다 가장 많이 쓴 기간을 보여 주고, Claude는 5시간 한도를 늘 함께 보여 주며 초기화까지 남은 시간을 붙인다. 두 CLI 모두 남은 한도를 묻는 공개 명령이 없으므로, CLI가 마지막으로 알려 준 값을 보여 준다.

- Claude: AgentHub에서 Claude 세션을 실행할 때 `stream-json`의 `rate_limit_event`를 받아 데이터 폴더의 `limits.json`에 저장한다. AgentHub에서 한 번도 실행하지 않았으면 비어 있고, CLI가 사용률 없이 상태만 보내면 "한도 임박"·"한도 도달"처럼 상태만 표시한다. 로그인한 계정의 사용량 API(Claude Code의 `/usage`와 같은 곳)에서도 1분마다 사용률을 읽고, 요청이 많아 거절(429)되면 몇 분 쉬었다가 다시 읽는다.
- Codex: `~/.codex/sessions` 기록에 남는 `rate_limits` 중 가장 최근 값을 읽는다. Codex 앱·CLI 어디서 쓰든 반영된다.

## 동작 방식

| 에이전트 | 첫 턴 | 이후 턴 |
| --- | --- | --- |
| Claude | `claude -p --output-format stream-json --verbose --session-id <uuid>` | `--resume <세션 ID>` |
| Codex | `codex app-server --listen stdio://`에서 `thread/start`·`turn/start` | 저장된 스레드를 `thread/resume`한 뒤 `turn/start` |

- 프롬프트는 명령줄 인자가 아니라 stdin으로 넘긴다. Codex는 JSON-RPC App Server 프로토콜로 대화·이미지·실행 중 승인 응답을 주고받으며 기존 CLI 로그인을 재사용한다. `app-server`를 지원하는 CLI가 필요하다(0.162.1에서 초기화·설정·대화 생성 확인). [OpenAI App Server 문서](https://learn.chatgpt.com/docs/app-server)를 따른다.
- 모델을 고르지 않은 Codex 세션은 `~/.codex/config.toml`의 기본 모델을 쓴다. 이 기본 모델이나 세션에 저장한 모델이 Codex 모델 목록(`~/.codex/models_cache.json`, 숨은 모델 포함)에 아예 없으면 지금 계정에서 쓸 수 없는 모델이다(예: "model is not supported when using Codex with a ChatGPT account"). 그때는 목록의 첫 모델로 바꿔 실행하고, 세션 기록과 모델 입력칸에 그 사실을 알린다. 추론 강도를 바꾼 모델이 지원하지 않으면 그 모델의 기본 강도를 쓴다. 이 목록은 마지막으로 받아 온 Codex 버전이 아는 모델만 담으므로, Codex 앱에는 있는 새 모델이 빠져 보이면 CLI를 업데이트한다(`npm i -g @openai/codex@latest`).
- 새 프로젝트 세션은 **프로젝트 원본 폴더**가 기본이다. 새 세션 창은 열 때마다 워크트리 미사용으로 시작한다. **워크트리에서 작업하기**를 직접 선택하고 이름을 입력하면 `<저장소>.agenthub/<이름>` 폴더와 `agenthub/<이름>` 브랜치를 현재 커밋에서 만든다. 커밋하지 않은 원본 수정은 포함하지 않는다. 이름은 영문·숫자·한글로 시작하는 1~64자의 영문·숫자·한글·하이픈·밑줄이며 Windows 예약어는 쓸 수 없다. 원본 폴더에서 같은 파일을 고치는 세션은 동시에 실행하지 않는다.
- 워크트리를 선택한 세션은 앱을 다시 시작하거나 재생성해도 같은 작업 폴더와 브랜치를 이어 쓴다. 이전 버전에서 원본으로 전환된 세션의 작업 폴더나 브랜치를 자동 복원하거나 합치지는 않는다. 가져온 CLI 기록은 원본 폴더에서 이어 쓴다.
- **변경 보기**는 세션을 만들 때의 커밋과 현재 작업 폴더의 차이를 보여 준다.
- 세션 기록은 데이터 폴더의 `sessions/`에, 설정은 `config.json`에 저장된다. 저장소의 `data/`는 git에 올리지 않는다.

## 권한 모드

| 에이전트 | 모드 | 의미 |
| --- | --- | --- |
| Claude | `plan` | 읽기와 계획만 한다. |
| Claude | `acceptEdits` (기본) | 파일 수정은 허용하고, 허용되지 않은 명령은 거부된다. |
| Claude | `bypassPermissions` | 모든 도구를 확인 없이 실행한다. 프로젝트 원본 폴더에도 적용된다. |
| Codex | `read-only` | 읽기만 한다. |
| Codex | `workspace-write` (기본) | 작업 폴더 안의 쓰기를 허용한다. |

Claude는 실행 중에 허용되지 않은 도구를 쓰려 하면 세션 화면에 **권한 요청** 카드가 뜨고, 답할 때까지 CLI가 기다린다. 허용·거부 중에 고르고, CLI가 규칙을 제안하면 **항상 허용**으로 같은 종류는 다시 묻지 않게 할 수 있다.

Codex도 실행 중 명령·파일 변경·네트워크·추가 권한에 대한 승인 요청을 카드로 표시하고 사용자 응답을 CLI에 돌려준다. **허용**은 해당 요청에만 적용한다. CLI가 지원하는 요청에는 **이번 실행에서 허용**을 고를 수 있으며 다음 요청에는 다시 물을 수 있다. **거절**하면 요청한 작업을 허용하지 않는다. 일반 채팅은 읽기 전용·승인 요청 없음으로 실행하고, CLI나 관리 정책에서 제한한 권한 및 지원하지 않는 요청은 자동으로 허용하지 않는다.

## 보안

서버는 `127.0.0.1`에만 열린다. Host 헤더와 `X-AgentHub` 헤더를 확인해 다른 웹사이트가 브라우저를 통해 명령을 실행하지 못하게 한다. 에이전트 CLI가 부르는 MCP 주소(`/mcp/<토큰>`)는 세션마다 서버가 켜질 때 새로 만드는 비밀 토큰으로 확인하고, 브라우저에서 온 요청(Origin 헤더)은 받지 않는다. 이 앱은 에이전트에게 파일 수정과 명령 실행을 맡기므로 외부에 노출하지 않는다.

## 코드 구조

- `public/app.js`는 화면 기능들을 조립한다. `public/features/`의 Controller가 API 요청과 화면 상태를 관리하고 View는 DOM을 그린다. 공통 HTTP·SSE·서버 상태 처리는 `public/shared/`와 `public/application/`에 둔다.
- `server/bootstrap.mjs`의 `createHub()`가 저장소·실행기·서비스를 조립한다. 생성 후 `start()`로 서버를 열고 `shutdown()`으로 닫는다. 모듈을 import하는 것만으로 서버를 시작하지 않는다.
- `server/transport/`는 HTTP·MCP·SSE 입출력, `server/application/`은 세션·프로젝트·메시지·워크플로의 업무 처리, `server/policies/`는 연락 권한과 연결 조건 같은 순수 판단을 맡는다.
- `server/infrastructure/persistence/`는 파일 저장을 담당한다. 서버와 저장소의 `dataDir`을 주입해 테스트용 데이터와 실제 기록을 분리한다. 기존 저장소 import 경로는 호환용 진입점으로 유지한다.
- `server/index.mjs`는 명령줄 실행 진입점이며, `electron/main.mjs`는 창과 앱 수명을 관리한다. 두 진입점이 같은 서버 조립 코드를 사용한다.

## 테스트

```bash
npm test
```

서버 통합 테스트는 임시 데이터 폴더를 사용한다. 화면 통합 테스트는 Windows에 Chrome이 설치되어 있으면 임시 프로필과 가짜 API로 실행하며, 실제 에이전트 작업을 시작하지 않는다. Chrome이 없는 환경에서는 브라우저 테스트만 건너뛴다.

## 알려진 한계

- 원본 폴더에서 작업하는 세션끼리 같은 파일을 동시에 고치면 서로의 수정을 덮을 수 있다. 이를 막는 파일 잠금은 없다.
- 여러 세션이 같은 Unity Editor를 동시에 쓰지 않도록 하는 잠금은 아직 없다.
- 이미지 처리와 승인 요청의 종류는 설치한 CLI와 선택한 모델이 지원하는 범위를 따른다. Codex의 지원하지 않는 서버 요청은 거절하고 기록에 이유를 남긴다.
