# AgentHub

Claude Code와 Codex 세션을 한 화면에서 만들고 이어 가는 Windows 데스크톱 앱이다. 여러 AI 세션에 일을 나눠 맡기고, 한 세션의 결과를 다음 세션으로 자동으로 넘길 수 있다.

각 AI의 CLI를 대신 실행하므로 이미 로그인한 구독 계정의 사용량 안에서 동작한다. API 키는 쓰지 않는다.

![세션 흐름](docs/images/session-flow.png)

- **여러 세션을 한곳에서**: Claude Code·Codex 세션을 프로젝트별로 모아 보고 이어서 대화한다.
- **세션 흐름**: "구현 → 리뷰 → 테스트"처럼 세션을 연결선으로 이어, 결과가 조건에 맞으면 다음 세션으로 넘긴다.
- **세션끼리 소통**: 연결된 세션끼리 필요할 때 서로 묻고 답한다.
- **Git 화면**: 바뀐 파일 확인, 스테이징, 커밋, 브랜치 병합, Pull Request까지 앱 안에서 한다.
- **작업과 팀 작업**: GitFlow 브랜치·작업 폴더·세션·PR을 한 작업으로 묶고, GitHub 이슈로 팀원과 작업을 주고받는다.
- **사용 한도 확인**: Claude·Codex 구독의 남은 사용량을 늘 보여 준다.

개발자용 안내(소스 실행, 빌드, 릴리스, 내부 구조)는 [docs/development.md](docs/development.md)에 있다.

## 설치

[Releases](https://github.com/Lyeol2/AgentHub/releases)에서 내려받는다.

- `AgentHub-Setup-<버전>.exe`: 설치형. 자동 업데이트를 받는다.
- `AgentHub-<버전>-portable.exe`: 설치 없이 실행한다.

필요한 것은 다음과 같다.

- git
- Claude Code CLI 또는 Codex CLI 중 쓰려는 것. 로그인되어 있어야 한다.

CLI가 없거나 로그인이 안 됐으면 앱 안에서 설치·로그인할 수 있다. 사이드바의 CLI 상태에 뜨는 **설치**·**로그인** 버튼이나 **설정 → CLI 경로 → 설치·업데이트·로그인**에서 Claude Code·Codex·GitHub CLI를 다룬다.

- 설치는 winget으로 한다. winget이 없거나 실행되지 않으면 먼저 자동으로 준비·복구하고, **Windows 패키지 관리자 (winget)** 항목에서 따로 **설치·복구**할 수도 있다. 그래도 안 되면 Claude Code는 공식 설치 스크립트, Codex는 npm으로 설치한다.
- 자동 설치가 안 되면 각 항목의 **수동 설치**에서 공식 다운로드 페이지와 설치 명령을 확인하고 복사할 수 있다.
- 로그인은 각 CLI의 브라우저 로그인을 실행하고, 로그인 주소와 일회용 코드를 창에 보여 준다. Claude가 코드를 붙여 넣으라고 하면 창에서 입력한다.
- **Codex·Claude CLI 자동 업데이트**는 기본으로 켜져 있다. 앱 시작 30초 후와 12시간마다 설치된 CLI를 업데이트하며, 실행 중인 작업이 있으면 끝날 때까지 미룬다. 설정에서 끄거나 각 CLI 카드의 **업데이트**로 직접 실행할 수도 있다.
- 업데이트는 기존 설치 방식과 경로를 따른다. npm·winget 또는 Claude 공식 설치를 확인할 수 없는 실행 파일과 다른 앱이 관리하는 CLI는 수동 업데이트 안내를 표시한다. 업데이트 방법은 [Codex 공식 안내](https://developers.openai.com/cookbook/examples/codex/using_goals_in_codex)와 [Claude Code 공식 안내](https://code.claude.com/docs/en/setup#update-manually)를 따른다.
- 진행 출력이 실시간으로 보이고, 끝나면 CLI 경로·버전·로그인 상태를 다시 확인한다. **새로고침**을 누르면 최신 상태를 새로 읽는다. 조회·설치·업데이트 오류가 나도 오류 카드에서 새로고침할 수 있고, 업데이트 실패는 **업데이트 다시 시도**로 재실행한다. 자동으로 찾지 못하면 설정에서 실행 파일을 직접 지정할 수 있다.

설치본의 세션 기록과 설정은 `%APPDATA%\AgentHub\data`에 저장된다. 창을 닫으면 실행 중인 AI를 멈추고 세션을 저장한 뒤 종료한다. 강제 종료 등으로 데이터 파일이 깨져도 그 파일만 데이터 폴더의 `corrupted/`로 옮기고 나머지로 시작한다.

## 처음 시작하기

![대시보드](docs/images/dashboard.png)

1. 앱을 열면 **대시보드**가 나온다. Claude Code·Codex로 작업한 적 있는 프로젝트가 자동으로 올라온다.
2. 기록이 없는 폴더는 **프로젝트 추가**(대시보드 또는 사이드바 프로젝트 옆 **+**)로 직접 추가한다.
3. **새 세션**을 눌러 첫 세션을 만든다.

대시보드에서는 전체 세션 수, 실행 중인 세션, 남은 사용 한도, 프로젝트 목록, 최근 세션을 한눈에 본다.

## 세션 만들고 대화하기

![새 세션](docs/images/new-session.png)

**새 세션**에서 다음을 고른다.

| 항목 | 설명 |
| --- | --- |
| 종류 | Claude Code 또는 Codex |
| 프로젝트 | 작업할 프로젝트 |
| 제목 | 세션 이름. 사이드바와 그래프에 보인다 |
| 역할 | 이 세션이 맡는 일, 고쳐도 되는 범위, 건드리면 안 되는 범위. 새 대화의 첫 요청에 붙는다 |
| 모델·추론 강도 | 비워 두면 CLI 기본값 |
| 권한 | 파일 수정·명령 실행을 어디까지 허용할지([권한 모드](#권한-모드)) |
| 워크트리 사용 | 기본은 **사용 안 함**으로 프로젝트 원본 폴더에서 일한다. **사용**을 고르고 이름을 입력하면 별도 작업 폴더·브랜치를 만든다. 기존 워크트리(작업 브랜치)를 골라 이어 쓸 수도 있다 |
| 오케스트레이터 세션 | 코드를 고치지 않고 다른 세션을 만들어 지휘하는 세션([오케스트레이터](#오케스트레이터)) |

![세션 화면](docs/images/session.png)

요청을 보내면 AI의 답변과 작업이 실시간으로 표시된다. 다음 요청은 같은 대화를 이어서 실행한다.

- **도구 호출**(파일 읽기·수정, 명령 실행 등)은 한 줄로 접혀 보이고, 누르면 입력과 출력이 펼쳐진다. 위의 **도구 펼치기**를 켜면 모두 펼쳐 둔다.
- 제목 옆과 그래프 카드 아래에 지금 작업의 경과 시간(`⏱ 3분 12초`)이 보인다.
- **변경 보기**는 세션을 만들 때부터 지금까지 바뀐 내용을 보여 준다.
- **설정**에서 모델·추론 강도·권한을 바꾸면 대화는 그대로 이어진다.

### 보내기·대기열·일시중지

입력창 옆 버튼 하나로 보내기·일시중지·재개를 한다.

| 상황 | 버튼 |
| --- | --- |
| 요청을 입력함 | **↑ 보내기** |
| 실행 중에 요청을 입력함 | **대기열에 추가**(끝난 뒤 차례로 보낸다) |
| 실행 중, 입력이 비어 있음 | **⏸ 일시중지**(Esc도 같다) |
| 멈춘 상태, 입력이 비어 있음 | **▶ 재개** |

- **일시중지**는 CLI에서 Esc를 누른 것처럼 멈추되 대화는 그대로 둔다. **재개**하면 멈춘 곳부터 이어서 진행한다. 일시중지 동안 넘어오는 작업과 메시지는 대기열에 쌓였다가 재개하면 차례로 보낸다.
- **중지**는 이어서 하지 않고 넘어온 작업도 버린다. 사용자가 대기열에 넣은 요청은 남긴다.
- Enter는 입력한 요청만 보낸다. 빈 Enter로는 멈추거나 재개하지 않는다.

끝난 요청은 최종 답변만 보이고, 작업 중 출력과 도구 실행 기록은 접어 둔다. 눌러서 다시 펼칠 수 있다.

### 첨부와 기록 내보내기·가져오기

- 입력창의 **첨부** 버튼, 끌어 놓기, **Ctrl+V**로 이미지나 파일을 붙인다. 데스크톱 앱에서는 Windows 탐색기에서 복사한 파일도 붙여넣을 수 있다. 요청당 4개, 파일당 10 MiB까지이고 폴더는 붙일 수 없다. 글 없이 첨부만 보내도 된다.
- 이미지(PNG·JPEG·GIF·WebP)는 AI가 그림으로 본다. 그 밖의 파일은 저장 경로를 함께 넘기고, 텍스트 파일은 앞부분 내용도 넘긴다. 일반 채팅에서는 이미지와 작은 텍스트 파일만 쓸 수 있다.
- **기록 내보내기**를 누르면 형식을 고른다. 세션 작업 폴더의 `docs/agenthub/` 아래에 새 파일을 만들고, 기존 파일은 덮어쓰지 않는다.
  - **세션 파일 (.agenthub)**: 요청·답변·도구 출력·질문과 권한 결정, 역할·모델·권한·장착한 스킬, 첨부 파일(합계 20MB까지)을 파일 하나에 담는다. 다른 세션에서 불러오거나 읽힐 때 쓴다. 작성창에서 `/export`로도 만든다.
  - **Markdown 문서 (.md)**: 사람이 읽기 좋은 문서로 저장하고, 기록 속 이미지와 파일은 옆 폴더에 복사한다.
  - 두 형식 모두 화면에 보이는 내용만 담고, API 키·토큰처럼 보이는 값은 `[가림]`으로 바꾼다.
- **기록 가져오기**(기록 내보내기 옆, **세션 목록** 탭, 또는 작성창의 `/import`)는 내보낸 `.agenthub`·`.md` 파일을 고른다. 프로젝트의 `docs/agenthub/` 파일을 고르거나, **다른 파일 선택…**으로 다른 PC·팀원에게서 받은 파일을 고른다(.agenthub 30MB, .md 5MB까지).
  - **새 세션으로 불러오기**: 기록을 새 세션으로 되살린다. `.agenthub` 파일은 같은 AI를 고르면 모델·권한·역할·스킬도 되살리고(확인 없이 실행하는 권한은 되살리지 않는다), 담긴 첨부도 다시 붙인다. **진행 상황 이어받기**를 켜 두면 가져온 기록을 새 대화의 첫 요청 앞에 붙여 이어서 작업한다.
  - **이 세션에 읽히기**(세션 화면에서 열었을 때): 지금 세션의 대화는 그대로 두고, 고른 기록을 정리해 다음 요청 하나 앞에 붙인다. 다른 세션이 한 일을 이어받거나 참고하게 할 때 쓴다. 한 번에 3개까지 붙인다.
  - 작성창에서 `@docs/agenthub/<이름>.agenthub`처럼 참조해도 그 세션 기록을 읽기 좋게 정리해 넘긴다.

### 작성창 명령 (@ 파일, / 스킬)

Claude Code·Codex처럼 작성창에서 `@`와 `/`를 쓴다. 두 CLI에서 똑같이 동작하도록 AgentHub가 풀어서 넘기고, 화면의 요청에는 입력한 그대로 남는다.

- **`@` 파일 참조**: `@`를 입력하면 세션 작업 폴더의 파일·폴더 목록이 뜬다. 이름 일부를 입력해 좁히고 ↑↓로 고른 뒤 Enter·Tab으로 넣는다. 폴더를 고르면 그 안을 이어서 고른다. 고른 파일은 작성창에 `@파일이름`으로 짧게 파란 글씨로 보이고(이름이 같은 파일이 있으면 상위 폴더를 붙여 구분한다), 보낼 때 전체 경로로 바뀐다. 보낼 때 64KiB 이하 텍스트 파일은 내용을, 큰 파일은 경로를, 폴더는 목록을 요청에 붙인다. 공백이 있는 경로는 `@"경로"`로 쓴다. 작업 폴더 밖 경로는 쓰지 않는다.
- **`/` 명령**: 요청 맨 앞에서 `/`를 입력하면 기본 명령과 이 프로젝트에서 쓸 수 있는 [스킬](#스킬)이 뜬다. `/스킬이름 할 일`로 보내면 AI가 그 스킬 지침을 먼저 읽고 할 일을 처리한다(장착하지 않은 스킬도 된다).
  - `/clear`: 다시 시작(CLI 대화를 새로 시작해 컨텍스트를 비운다)
  - `/export`: 세션을 `.agenthub` 파일로 내보낸다
  - `/import`: 기록 가져오기 창을 연다
- 목록이 열려 있을 때 Enter는 고르기만 하고 보내지 않는다. Esc는 목록만 닫는다.
- 대기열에 넣은 요청과 버튼 노드의 프롬프트도 같은 방식으로 풀어 쓴다. 다른 세션에서 넘어온 글은 풀어 쓰지 않는다. 일반 채팅에서는 쓰지 않는다.

### 세션 잠금

세션 카드·목록의 **자물쇠 아이콘**을 누르면 그 세션의 채팅을 열 수 없게 잠근다. 다시 누르면 풀리고, 재시작 후에도 유지된다. 잠가도 버튼·연결로는 실행되므로, 채팅을 열지 않고 결과만 [Markdown 출력](#버튼markdown-출력-노드) 노드에서 볼 수 있다.

### 세션의 AI 바꾸기

세션 **설정**에서 AI(Claude ↔ Codex)를 바꿀 수 있다. 실행 중이 아닐 때만 바꿀 수 있다.

- CLI가 달라지므로 대화는 새로 시작한다. 작업 폴더·브랜치·역할·연결·스킬·화면 기록은 그대로 둔다.
- **진행 상황 이어받기**(기본으로 켜짐)는 지금까지의 요청·답변·도구 사용·바뀐 파일 목록을 정리해 새 AI의 첫 요청 앞에 붙인다.
- 모델은 비우고(CLI 기본값), 권한은 비슷한 것으로 옮긴다(Claude `plan` ↔ Codex `read-only`, `acceptEdits` ↔ `workspace-write`, `bypassPermissions` ↔ `danger-full-access`).

## 일반 채팅

![일반 채팅](docs/images/chat.png)

사이드바의 **새 채팅**은 프로젝트와 상관없이 AI와 대화하는 창이다. 파일을 고치지 않고 읽기 전용으로 실행한다. 위에서 AI·모델·추론 강도를 바꿀 수 있고, 보내기·일시중지·이미지 첨부는 세션과 같다. 일반 채팅은 연결·워크트리·기록 내보내기를 쓰지 않는다.

## 세션 흐름으로 일 나누기

프로젝트를 누르면 **세션 흐름** 탭에 세션이 카드로 나온다. 카드 사이를 연결선으로 이으면, 한 세션의 결과가 조건에 맞을 때 다음 세션의 요청으로 자동으로 넘어간다.

![세션 흐름](docs/images/session-flow.png)

위 예시는 이렇게 동작한다.

1. **구현** 세션이 일을 마치고 답변 마지막 줄에 "검토 요청"을 쓰면 **리뷰** 세션으로 넘어간다.
2. 리뷰가 "수정 필요"를 쓰면 구현으로 되돌아가고, "통과"를 쓰면 **테스트** 명령이 실행된다.
3. 테스트가 성공하면 **문서 정리** 세션으로 넘어간다.

### 그래프 다루기

| 하고 싶은 일 | 방법 |
| --- | --- |
| 세션 열기 | 카드를 두 번 누른다(Ctrl·Shift+두 번 누르기는 새 창) |
| 여러 카드 고르기 | Ctrl·Shift를 누르고 누르거나, 빈 곳을 끌어 선택 상자를 그린다 |
| 카드 옮기기 | 끌어서 옮긴다. 위치는 저장된다 |
| 지우기 | 고른 뒤 **Delete**. 작업 폴더와 CLI 원본 기록은 남는다 |
| 확대·축소 | 마우스 휠, 또는 위의 −·+·**맞춤** 버튼 |
| 화면 이동 | 휠 버튼을 누른 채 끈다 |
| 연결하기 | 카드 오른쪽 ● 손잡이를 다른 카드로 끌어 놓는다 |
| 새 세션·명령을 만들며 연결 | ● 손잡이를 빈 곳에 놓는다 |
| 새 세션·명령 만들기 | 빈 곳을 우클릭한다 |
| 되돌리기·다시 실행 | **Ctrl+Z** / **Ctrl+Y**(또는 Ctrl+Shift+Z), 위의 ↶·↷ 버튼 |
| AI에게 맡기기 | 그래프 아래 입력창에 할 일을 적는다(아래 흐름 도우미) |

되돌리기는 카드 이동·자동 배치, 연결 만들기·설정 변경·삭제, 명령 등 노드 만들기·편집·삭제, 노드 그룹 만들기·해제에 쓸 수 있다. 지운 노드는 같은 설정과 연결로 다시 만들지만 실행 기록은 되살리지 않고, 웹훅 받기 노드는 새 주소를 받는다. 세션 만들기·삭제, 흐름 도우미 적용, 실행은 되돌리지 않는다. 기록은 열어 둔 화면에만 남으며 다른 프로젝트로 옮기면 비워진다.

### 흐름 도우미

세션 흐름 아래 입력창에 "구현 세션 뒤에 Codex 리뷰 세션을 만들고 '검토 요청'이면 넘겨 줘"처럼 적고 Enter를 누른다. AI가 지금 그래프를 보고 할 작업 목록을 만들어 보여 주며, **적용**을 눌러야 반영된다.

- 세션·노드 만들기, 세션 역할 정하기, 이름 바꾸기, 연결하기, 세션에 요청 보내기를 할 수 있다. 노드를 지우거나 Git 노드·결과 모으기를 만드는 일은 하지 않는다.
- 카드를 골라 두면 함께 보낸다. "이 세션 역할을 테스터로 바꿔 줘"처럼 고른 카드를 가리킬 수 있다.
- 적용은 직접 만들 때와 같은 검사를 거친다. 미리 본 뒤 그래프가 바뀌어 맞지 않는 작업이 있으면 적용하지 않는다. 새로 만든 노드는 적용 후 선택된 상태가 된다.
- 명령 만들기와 같이 Claude CLI(없으면 Codex)를 한 번 호출한다. 프로젝트 파일은 읽기만 한다.

### 연결 설정

![연결 설정](docs/images/link-dialog.png)

연결선의 라벨을 누르면 연결 설정이 열린다.

- **넘기는 조건**: 답변 마지막 줄에 키워드가 있으면 / 턴이 성공하면 / 턴이 실패하면 / 다른 연결이 모두 안 맞으면(그 외) / 턴이 끝날 때마다 / 수동으로만
- **키워드**: 답변의 마지막 줄에서만 찾는다. 쉼표로 여러 개를 적을 수 있다. "수정 필요 없음"처럼 키워드 뒤에 부정이 붙으면 맞지 않은 것으로 본다. 보내는 세션의 역할에 적힌 판정 말을 후보로 보여 준다.
- **받는 세션에 줄 지시**: 넘길 때 함께 보낼 말. 비워 두면 "이 결과를 이어받아 네 역할에 맞게 처리하라"로 보낸다.
- **넘기기 전에 승인 받기**: 켜면 조건이 맞아도 연결선 위에 "승인 대기"로 멈춘다. ✓를 눌러야 넘어간다.
- **지금 넘기기**: 조건과 상관없이 지금 넘긴다. "수동으로만" 연결은 이 버튼으로만 넘어간다.

넘어갈 때는 보낸 세션의 마지막 답변, 바뀐 파일 목록, 작업 폴더가 받는 세션의 요청으로 들어간다. 받는 세션이 실행 중이면 끝난 뒤 시작한다. 한 세션에서 나가는 연결은 키워드 → 성공·실패 → 그 외 순서로 먼저 맞은 쪽만 따라가고, "턴이 끝날 때마다"는 언제나 함께 넘긴다. 서로를 가리키는 연결이 끝없이 돌지 않도록 자동 연결은 한 흐름에서 8단계까지만 이어진다.

### 명령 노드

`npm test` 같은 셸 명령을 그래프의 카드로 둘 수 있다. 그래프 빈 곳을 우클릭하거나 ● 손잡이를 빈 곳에 놓은 뒤 **새 명령**을 고른다. 연결로 넘어오면 명령을 실행하고, 종료 코드 0이면 성공, 아니면 실패로 다음 연결을 고른다. 키워드 조건은 출력 전체에서 찾는다. 카드의 ▶ 버튼으로 직접 실행할 수도 있다.

### Git 노드

그래프 빈 곳을 우클릭해 **새 GIT**를 만들고 **브랜치 사용** 또는 **브랜치 병합**을 고른다. 기존 로컬 브랜치 목록에서 선택하며, 병합은 소스 브랜치 하나를 대상 브랜치 하나에 반영한다.

- **브랜치 사용**은 기존 작업 폴더를 재사용하고, 없으면 해당 브랜치의 워크트리를 준비한다. 성공 연결의 **Git 작업 폴더 사용**을 켜면 후속 세션이나 명령이 그 폴더에서 실행된다. 새 세션과 같은 폴더의 세션에 적용할 수 있으며, 기존 대화가 있는 다른 폴더의 세션은 옮기지 않는다. 명령 노드는 실행 폴더도 **이전 노드의 작업 폴더**로 설정한다.
- **브랜치 병합**은 대상 작업 폴더에서 `--no-ff`로 병합한다. 소스의 커밋된 변경만 반영하며, 대상에 커밋하지 않은 변경이나 진행 중인 Git 작업이 있으면 실패한다. 관련 세션이 진행 중이면 실행하지 않는다. `main`·`develop`은 병합 대상으로 선택할 수 있다.
- 오른쪽 **성공**·**실패** 손잡이를 다음 세션·명령·Git 노드에 연결한다. 이미 병합된 상태도 성공이다. 충돌하면 이번 병합을 취소하고 충돌 파일을 실패 출력에 담는다. **결과 보기**에서 작업 폴더·커밋·오류·복구 필요 여부를 확인한다.
- 버튼을 Git 노드에 연결해 시작할 수 있다. 사용자가 중지한 실행은 다음으로 넘기지 않는다. 중단·시간 초과·앱 종료로 결과가 불확실하면 실제 Git 상태를 확인한 뒤 다시 실행한다.

### 버튼·Markdown 출력 노드

그래프 빈 곳을 우클릭해 **새 버튼**이나 **새 Markdown 출력**을 만든다. `버튼 → 세션 → Markdown 출력`으로 이으면 버튼 한 번으로 작업을 시작하고 결과를 파일로 남길 수 있다.

- **버튼**에는 연결된 세션에 보낼 프롬프트를 적는다. **실행**을 누르면 연결 조건에 맞는 세션에 요청을 보낸다. 대상이 실행 중이면 대기열에 들어간다. 버튼은 흐름의 시작점이며 세션·결과 모으기·Git 노드에 연결할 수 있다.
- **Markdown 출력**은 보낸 세션의 마지막 완료 메시지 원문을 `docs/agenthub/outputs/`에 매번 새 `.md` 파일로 저장한다. AI나 셸을 부르지 않는다. **결과 보기**에서 최신 파일을 미리보고 내려받는다.

### 노드 그룹

AI 세션, 명령줄, GIT, 버튼, Markdown 출력, 결과 모으기 등 모든 종류의 노드를 큰 박스 하나에 넣을 수 있다. 여러 노드를 선택하고 **Ctrl+G** 또는 우클릭 메뉴에서 **노드 그룹 만들기**를 선택한다.

- 그룹을 펼치면 내부 노드와 연결을 편집하고, 접으면 그룹 이름·진행 상태·입출력 포트가 있는 하나의 노드로 표시한다. 그룹을 옮기면 내부 노드도 함께 이동한다.
- 그룹 편집에서 멤버를 넣거나 꺼내고 이름·입출력 포트를 정한다. 노드 하나는 한 그룹에 속하며 그룹 중첩은 지원하지 않는다.
- 입력 포트는 지정한 내부 노드의 입력으로, 출력 포트는 내부 노드의 성공·실패 등 조건별 출력으로 연결한다. 외부로 이어져 있던 연결은 경계 포트로 자동 노출된다.
- 포트는 기존 연결의 별칭이다. 접기·펼치기·이동은 실행 순서, 조건, 승인 대기, 작업 폴더, 세션 권한을 바꾸지 않는다. 내부 노드를 직접 실행해도 나머지 멤버가 자동 실행되지 않는다.
- **그룹 해제**는 박스만 제거한다. 내부 노드와 연결, 대화 기록은 유지된다. 그룹 위치·크기·멤버·포트 이름·접힘 상태는 재시작 후에도 유지된다.

### 결과 모으기 노드

AI 세션·명령·Git·입력·반복·가공 노드의 결과를 함께 기다리고 다음 노드로 넘긴다. 구성원은 같은 프로젝트에서 최대 20개까지 고른다. 큰 박스인 **노드 그룹**과 별개의 실행 노드다.

- 우클릭 → **새 결과 모으기**에서 구성원을 고른다. 버튼이나 입력 폼을 결과 모으기에 연결하면 구성원에게 같은 실행 요청을 나눠 보낸다.
- 자동 합류는 **같은 실행의 결과가 모두 도착했을 때 한 번만** 일어난다. 이전 실행의 답변이나 명령 출력은 섞지 않는다. 반복 중 다시 합류하려면 구성원 모두의 새 결과가 필요하다.
- 구성원이 결과 모으기로 보낸 연결은 완료 신호로 처리하고 구성원을 다시 실행하지 않는다.
- 하나라도 실패하면 **실패**, 모두 성공하면 **성공** 연결을 따른다. 각 구성원의 완료 시점 출력과 작업 폴더를 함께 전달하며, MD 출력에도 저장할 수 있다.
- **지금 넘기기**는 진행 중인 구성원이 없을 때 최신 결과를 수동으로 모은다. 자동 실행의 합류와 달리 사용자가 현재 결과를 선택해 넘기는 동작이다.

### 입력 폼 노드

실행할 때 필요한 값을 입력받고, 같은 흐름의 다음 노드들에서 재사용한다. 우클릭 → **새 입력 폼**에서 항목 이름·키·한 줄/여러 줄/숫자·필수 여부·기본값을 정한다. 실행 버튼을 누르면 입력 화면이 열린다.

- 요청과 연결 지시에 `{{request}}`처럼 입력 키를 적는다. `{{input}}`과 `{{output}}`은 연결에서 넘어오는 현재 출력이다. 없는 변수는 오류로 표시한다.
- 명령에는 입력값을 코드로 끼워 넣지 않고 환경 변수로 전달한다. 키가 `request`이면 PowerShell에서는 `$env:AGENTHUB_REQUEST`, sh에서는 `$AGENTHUB_REQUEST`로 읽는다. 전체 값은 `AGENTHUB_INPUT_JSON`이다.
- 키는 영문·숫자·밑줄로 적고, 영문이나 밑줄로 시작한다. 대소문자만 다른 키는 함께 쓸 수 없으며 `input_json`은 예약되어 있다.
- 입력 폼은 시작점이므로 들어오는 연결이 없다. 다음 실행을 대기열에 넣어도 앞 실행의 입력값을 바꾸지 않는다.

### 반복 제어 노드

성공 출구는 **반복할 작업**, 실패 출구는 **횟수 초과**다. 최대 1~20회와 실행 사이 대기 시간을 정한다.

`입력 폼 → 반복 → 구현 AI → 테스트 명령`으로 연결하고, 테스트 실패를 반복 노드로 되돌린다. 테스트 성공은 완료 노드로 연결한다. 반복 한도가 3이면 작업을 세 번 실행한 뒤 다음 진입에서 횟수 초과로 나간다. 새 흐름을 시작하면 횟수가 초기화된다.

여러 실행이 겹치면 입력값과 반복 횟수를 각각 보존해 차례로 처리한다. 중지한 흐름은 승인 대기 중인 연결을 나중에 승인해도 재실행하지 않는다.

### 결과 가공 노드

AI 답변이나 명령·Git 출력을 필요한 부분만 골라 다음 노드에 전달한다. AI나 셸을 새로 실행하지 않는다.

- **JSON 경로**: `tests.failures`, `items[0].name` 같은 경로로 값을 꺼낸다. 빈 경로는 전체 JSON이다.
- **줄 추출**: 지정한 문자가 포함된 줄만 남긴다. 조건을 비우면 빈 줄을 제거한다.
- **템플릿**: `{{input}}` 또는 `{{output}}`과 입력 변수로 전달할 글을 구성한다.
- 잘못된 JSON·없는 경로·없는 변수는 실패 출구로 보낸다. 카드의 **결과 보기**에서 가공 결과를 확인한다.

### 파일 감시 노드

프로젝트 안의 파일이나 폴더가 바뀌면 연결된 흐름을 시작한다. 감시 경로는 프로젝트 기준 상대 경로이며 최대 20개다.

- **감시 시작**을 눌러 켜고 **감시 중지**로 끈다. 앱을 다시 실행하면 감시는 꺼진 상태로 시작한다.
- 변경 대기 시간(100~60000ms) 동안 발생한 변경을 묶어 한 번 실행한다. 앞 실행이 진행 중이거나 승인을 기다리면 추가 변경을 모았다가 끝난 뒤 실행한다.
- 요청에서 `{{paths}}` 또는 `{{changedFiles}}`로 변경 파일 목록, `{{changedAt}}`으로 감지 시각을 사용한다.
- `.git`, `node_modules`, `data`와 프로젝트 밖을 가리키는 경로는 감시하지 않는다. 파일을 교체 저장해도 다음 변경을 계속 감지한다.
- 감시를 중지하면 새 변경을 전달하지 않는다. 이미 시작한 후속 작업은 해당 작업의 중지 버튼으로 멈춘다.

### 시간 예약 노드

그래프 빈 곳 우클릭 → **새 시간 예약**에서 지정한 시각에 연결된 흐름을 시작한다. `시간 예약 → AI 세션 → 알림`처럼 연결해 쓴다.

- **한 번 실행**은 날짜와 시각, **매일**은 실행 시각, **일정 간격**은 1~10080분 간격을 정한다. 매일 예약은 AgentHub가 실행되는 PC의 시간대를 기준으로 한다.
- 새 노드는 꺼진 상태다. **예약 시작**을 누르면 카드에 다음 실행 시각이 표시되고, **예약 중지**로 해제한다. 설정을 바꾸려면 먼저 예약을 중지한다.
- AgentHub가 실행 중일 때만 동작한다. 앱을 다시 열면 켜 두었던 예약을 복원한다. 종료 중에 지난 반복 예약은 건너뛰고, 지난 일회 예약은 오류로 표시해 날짜를 다시 정할 수 있다.
- 같은 예약의 앞 흐름이 실행·일시중지·승인 대기 중이면 해당 회차를 건너뛴다. 밀린 예약을 쌓거나 한꺼번에 실행하지 않는다.
- CLI 업데이트와 예약 시각이 겹치면 해당 AI 요청을 대기열에 보관하고 업데이트가 끝난 뒤 실행한다.
- 전달할 요청에서 `{{scheduledAt}}`은 예정 시각, `{{triggeredAt}}`은 실제 시작 시각을 나타낸다(시간대가 포함된 ISO 형식). 다음 노드에서도 같은 변수를 사용할 수 있다.
- 예약은 시작점이므로 들어오는 연결이나 결과 모으기의 구성원으로 사용할 수 없다. 예약 중지는 이후 실행을 해제하며, 이미 시작한 작업은 해당 작업 또는 흐름 전체 중지로 멈춘다.

### 실행 기록·흐름 전체 중지·재개

그래프 위의 **실행 기록**을 누르면 이 프로젝트에서 시작한 흐름을 실행별로 볼 수 있다. 각 단계의 입력·출력·오류·소요 시간과 대기·승인 상태를 저장하며 앱을 다시 열어도 남는다. 완료 기록은 최근 200개를 보관하고, 진행 중인 기록은 보관 한도 때문에 지우지 않는다.

- **이 흐름 전체 중지**는 선택한 실행에 속한 AI·명령·반복 대기·대기열·승인 대기를 함께 멈춘다. 다른 실행과 그 실행의 대기 요청은 유지한다. 해당 실행을 시작한 파일 감시·시간 예약도 해제한다.
- 실행이 실패·중지·중단되면 단계를 골라 **선택한 단계부터 재개**한다. 새 실행 기록을 만들고 원래 입력값을 사용한다. 앞서 성공한 독립 단계의 결과는 **기존 결과 사용**으로 표시하고, 실패 지점 이후 결과는 다시 만든다.
- 같은 노드가 다른 작업을 실행 중이거나 작업 폴더가 바뀌었다면 재개하지 않고 이유를 표시한다. 이미 종료한 실행의 승인 버튼으로 중지된 흐름을 되살릴 수 없다.
- 앱 종료로 끝나지 못한 실행은 다음 시작 때 **중단됨**으로 표시한다. 자동 실행하지 않으며, 사용자가 재개한다. 승인 대기에서 중단된 단계는 새 실행에서도 다시 승인을 받는다.
- 재개는 현재 노드 설정을 사용한다. 명령이나 가공 조건을 고친 다음 실패한 단계부터 다시 시도할 수 있다. 노드를 삭제했으면 해당 단계는 재개할 수 없다.

### 그룹 템플릿

큰 노드 그룹의 우클릭 메뉴나 편집 화면에서 **템플릿으로 저장**한다. 그래프 위의 **그룹 템플릿**에서 저장한 구성을 같은 프로젝트나 다른 프로젝트에 추가한다.

- AI·명령·Git·입력·반복·가공·감시·예약·알림 등 내부 노드의 설정과 위치, 내부 연결, 경계 포트, 결과 모으기 구성원을 함께 저장한다.
- 복원할 때 노드와 연결에 새 ID를 주고 내부 참조를 다시 연결한다. 대화 기록·CLI 대화 ID·작업 폴더 소유권·태스크·실행 결과·승인 대기는 복사하지 않는다. 파일 감시와 시간 예약은 꺼진 상태로 만든다.
- 결과 모으기의 구성원이 그룹 밖에 있으면 저장할 수 없다. 템플릿을 추가할 프로젝트에 Git 브랜치 등 필요한 설정이 없으면 생성 전에 이유를 알린다.
- 템플릿 목록은 프로젝트 간 공용이다. 원래 그룹을 지워도 저장한 템플릿은 남으며, 템플릿을 지워도 이미 추가한 노드들은 남는다.
- 추가 도중 실패하면 이번에 만든 노드·연결·박스만 되돌리고 기존 그래프를 보존한다.

### 알림 노드

우클릭 → **새 알림**으로 만든다. 완료·실패·입력 대기를 알리고 싶은 연결에 넣고 제목·메시지·정보/성공/실패·소리를 정한다. 메시지에는 `{{input}}`·`{{output}}`과 흐름의 입력 변수를 쓸 수 있다. 알림 후에도 다음 노드로 연결할 수 있다.

- 앱 안에 알림을 표시하고 해당 실행 기록에도 남긴다.
- 그래프의 **알림 설정**에서 데스크톱 알림을 켤 때만 브라우저 알림 권한을 요청한다. 권한을 거절해도 앱 안의 알림과 기록은 사용할 수 있다.
- 소리는 노드의 소리 설정과 사용자의 소리 허용이 모두 켜져 있을 때 재생한다.

### 웹훅 노드

**웹훅 보내기**(우클릭 → 출력)는 앞 노드의 결과를 지정한 주소로 보낸다. Slack·Discord 알림이나 사내 API 호출에 쓴다.

- 요청 방식(POST·PUT·PATCH·GET·DELETE), 머리글("이름: 값"을 한 줄에 하나씩), 본문(JSON 또는 텍스트), 응답 대기 시간을 정한다.
- 본문과 머리글에 `{{input}}`과 흐름의 입력 변수를 쓸 수 있다. JSON 본문에서는 값을 자동으로 이스케이프하므로 `{"text": "{{input}}"}`처럼 따옴표 안에 쓴다.
- 2xx 응답이면 성공으로 보고 응답 본문을 다음 노드에 넘긴다. 아니면 실패 연결로 상태 코드와 본문을 넘긴다.

**웹훅 받기**(우클릭 → 시작)는 노드마다 만들어지는 주소(`http://127.0.0.1:<포트>/hooks/<비밀 값>`)로 POST 요청이 오면 흐름을 시작한다.

- 받으면 보낼 요청에 `{{body}}`(본문), `{{payload.필드}}`(JSON 본문의 값), `{{event}}`(`X-GitHub-Event` 등), `{{query.이름}}`, `{{method}}`, `{{receivedAt}}`을 쓸 수 있다.
- 주소의 비밀 값이 인증이다. 새어 나갔으면 편집 창에서 **주소를 새로 만들기**로 바꾼다. **요청 받기**를 끄면 요청을 받지 않는다. 브라우저에서 보낸 요청은 받지 않으며, 노드 하나에 1분에 60번까지 받는다.
- AgentHub는 이 PC에서만 열려 있다. GitHub 같은 외부 서비스에서 보내려면 ngrok 같은 터널을 AgentHub 포트에 연결하고 터널 주소 뒤에 `/hooks/<비밀 값>`을 붙여 등록한다.
- 카드의 **시험 실행**은 빈 요청을 받은 것처럼 흐름을 시험한다. 그룹 템플릿으로 추가한 웹훅 받기 노드는 새 주소를 받는다.

### 오케스트레이터

프로젝트 화면의 **오케스트레이터 만들기**(또는 새 세션에서 **오케스트레이터 세션**)로 지휘 세션을 만든다. 오케스트레이터는 코드를 읽기만 하고 고치지 않는다.

1. 오케스트레이터에 목표를 보낸다.
2. 오케스트레이터가 만들 세션, 연결, 보낼 요청을 담은 계획을 쓰면 세션 화면에 계획 카드가 뜬다.
3. **승인하고 실행**하면 세션을 만들고 연결한 뒤 요청을 보낸다. **거절**에 이유를 적으면 계획을 고친다.
4. 결과가 오케스트레이터로 돌아오게 연결하면, 다음 계획을 세우거나 끝났다고 보고한다.

계획은 매번 사람이 승인해야 실행된다. 한 계획에서 새 세션은 8개까지 만들 수 있고, 그래프에는 오케스트레이터가 만든 세션으로 점선 지휘선이 그려진다.

## 세션끼리 소통

연결이 정해진 순서로 결과를 넘기는 것이라면, 메시지는 AI가 필요할 때 스스로 다른 세션에 말을 거는 통로다.

- 연결선으로 **직접** 이어진 세션끼리만 메시지를 주고받는다. 연결 방향은 상관없고, 꺼진 연결이나 다른 세션을 거친 간접 연결로는 보낼 수 없다.
- AI는 다른 세션의 이름·역할·상태를 보고, 메시지를 보내거나, 답이 올 때까지 기다리며 물을 수 있다.
- 받는 세션이 일하는 중이면 지금 작업에 바로 끼워 넣거나, 끝난 뒤 다음 요청으로 받는다.
- 주고받은 메시지는 세션 기록에 남고, 그래프에는 점선 대화선으로 보인다(마우스를 올리면 마지막 메시지).
- 프로젝트 화면의 **공유 노트**는 세션들이 함께 읽고 덧붙이는 메모장이다. 사용자도 보고 고칠 수 있다.

## 스킬

스킬은 "이런 작업은 이렇게 하라"는 작업 지침 파일(`<이름>/SKILL.md`, Claude Code·Codex 공통 형식)이다. 프로젝트 화면의 **스킬** 버튼이나 그래프 빈 곳 우클릭 → **스킬 관리**에서 만들고 고치고 옮긴다. 세션 카드의 스킬 칩을 누르면 그 세션에 스킬을 장착한다.

| 범위 | 위치 | 쓰는 세션 |
| --- | --- | --- |
| 프로젝트 (새 스킬 기본) | `<프로젝트>/.agenthub/skills` | AgentHub에서 장착한 세션만 |
| Claude 프로젝트 | `<프로젝트>/.claude/skills` | Claude가 그 프로젝트에서 저절로 쓴다 |
| 개인 | `~/.claude/skills`와 `~/.agents/skills` | Claude·Codex가 모든 프로젝트에서 저절로 쓴다 |

이름이 겹치면 프로젝트 → Claude 프로젝트 → 개인 순으로 앞의 것을 쓴다.

장착하지 않아도 작성창에서 `/스킬이름 할 일`로 그 스킬을 한 번 실행할 수 있다([작성창 명령](#작성창-명령--파일--스킬)).

## 작업 탭

프로젝트 화면은 **세션 흐름** · **세션 목록** · **작업** · **Git** · **팀 작업** · **팀원** 탭으로 나뉜다. **작업** 탭은 요구사항 하나를 브랜치·전용 작업 폴더·AI 세션·Pull Request까지 한 작업으로 묶는다.

- **새 작업**에서 제목·유형·담당 AI를 고르면 브랜치와 작업 폴더, 연결 세션을 함께 만든다. 기능 개발은 최신 `develop`에서 `feature/*`, 긴급 수정은 최신 `main`에서 `hotfix/*`, 배포 준비는 `develop`에서 `release/*`로 시작한다.
- **워크트리**에서 **워크트리 만들지 않기**을 고르면 별도 작업 폴더 없이 원본 폴더를 새 작업 브랜치로 바꿔 그 자리에서 일한다. 원본 폴더에 커밋하지 않은 변경이 없어야 하고, 원본 폴더를 쓰는 작업은 한 번에 하나다. **정리**하면 원본 폴더를 작업 전 브랜치로 되돌린다.
- 브랜치를 새로 만들지 않고 **기존 작업 브랜치**를 골라 그 폴더와 커밋하지 않은 변경을 이어 쓸 수도 있다. 일반 **새 세션**에서도 같은 목록에서 고를 수 있다.
- **GitFlow 설정**에서 프로젝트마다 기준 브랜치 이름(예: `Develop`)과 접두어를 바꿀 수 있다. 바꿔도 기존 브랜치와 이미 만든 작업은 그대로다.
- **작업 마무리**에서 커밋 메시지·설명·검증 결과를 확인하고 커밋·게시·PR 생성까지 한다. PR을 만들면 "리뷰 대기", 실제로 병합되면 "병합 완료"가 된다. 병합한 작업은 **정리**로 작업 폴더와 로컬 브랜치를 지운다.

자세한 조건은 [작업 흐름 문서](docs/tasks.md)에 있다.

## Git 탭

프로젝트 화면의 **Git** 탭에서 커밋까지 끝낼 수 있다.

![Git 변경사항](docs/images/git-changes.png)

- **변경사항**: 바뀐 파일을 스테이징하거나 해제하고, 파일을 누르면 diff를 본다. 메시지를 적고 **커밋**하면 스테이징한 내용만 담는다.
- 기본 세션은 프로젝트 원본 폴더에서 일하므로 고친 파일이 여기에 바로 보인다. 워크트리를 쓰는 세션의 변경은 그 작업 폴더와 브랜치에 남는다.

![Git History](docs/images/git-history.png)

- **History**: 모든 로컬 브랜치의 최근 커밋을 노선도로 보여 준다. 점선은 아직 커밋하지 않은 작업이다. 세션 브랜치는 세션 이름으로 표시한다. 커밋을 누르면 변경 내용이 열린다.
- 브랜치의 **체크아웃**으로 원본 폴더를 그 브랜치로 바꾼다. 커밋하지 않은 변경은 그대로 가져가고, 그 브랜치 내용과 겹치면 체크아웃하지 않는다. 원본 폴더에서 세션이 실행 중이거나 다른 작업 폴더에서 쓰는 브랜치는 바꿀 수 없다. History에서 브랜치 끝 커밋을 두 번 눌러도 그 브랜치로 체크아웃한다.
- 현재 브랜치보다 앞선 커밋이 있는 브랜치는 차이를 보고 현재 브랜치로 **병합**할 수 있다. 충돌이 나면 되돌린 뒤 충돌한 파일을 알린다.
- **Pull Requests**: GitHub 저장소의 PR 목록, 설명·검사 상태·diff를 보고, 현재 브랜치로 PR을 만들고, 병합(Merge/Squash/Rebase)하거나 닫는다. GitHub CLI 설치·로그인이 필요하다.
- 강제 push·pull·fetch, 포크 간 PR 생성은 지원하지 않는다.

## 팀 작업

서버 없이 **GitHub 계정과 GitHub Issues**로 팀원끼리 작업을 주고받는다. 팀원은 저장소 협업자이고, 작업 내용과 대화는 GitHub 이슈에만 남는다.

- **계정 연결**: 사이드바 아래 **GitHub 계정 연결**(또는 **설정 → 계정**)을 누르면 GitHub CLI로 브라우저 로그인한다. 토큰은 AgentHub가 저장하지 않는다.
- **작업 보내기**: **팀 작업** 탭의 **작업 보내기**, 또는 세션 우클릭 → **팀원에게 넘기기…**(세션의 요청·마지막 답변·바뀐 파일로 초안을 채운다). 받을 팀원을 고르면 이슈를 만든다. 공개 저장소면 공개된다고 경고한다.
- **팀원**: **팀원** 탭에서 이 저장소에서 작업을 받을 수 있는 팀원과 각자 맡은 열린 작업 수를 보고, 바로 **작업 보내기**를 누른다. 팀원 이름은 GitHub 프로필의 Name을 불러오고, 직접 붙인 이름은 이 컴퓨터에만 저장된다. 작업 보내기 창에서도 고른 팀원의 이름을 바꿀 수 있다.
- **받은 작업**: 나에게 지정된 작업을 사이드바 **받은 작업**과 팀 작업 탭에 보여 주고, 새 작업이 오면 알림을 띄운다.
- **시작하기**: 작업 상세에서 AI를 고르고 **세션으로 시작**을 누른다. 자동으로 시작하지 않는다. AI에게는 이슈 내용과 저장소 권한이 있는 사람·작성자·담당자의 댓글만 넘긴다.
- **대화**: 이슈 댓글을 대화처럼 보고 바로 쓴다. **진행 댓글**을 켜 두면 연결된 세션의 판정·실패를 댓글로 남긴다.
- **되돌려 보내기·닫기**: 사유를 남기고 보낸 사람에게 돌려주거나 완료로 닫는다.
- **PR 연결**: Git 탭에서 PR을 만들 때 **연결할 작업**을 고르면, PR이 병합될 때 작업도 닫힌다.

## 기존 Claude Code·Codex 세션 가져오기

AgentHub 밖(Claude Code·Codex 앱이나 CLI)에서 연 세션도 가져와 이어 쓸 수 있다.

1. 프로젝트를 누르고 **세션 목록** 탭 아래의 **Claude Code · Codex 세션**을 본다.
2. **가져오기**를 누르면 대화 기록(최근 400개 항목)이 보이고, 다음 요청부터 같은 대화를 이어서 실행한다.

원래 기록 파일은 읽기만 한다. 같은 세션을 다른 앱에서 동시에 이어 쓰면 기록이 엇갈릴 수 있다.

**프로젝트 제거**(프로젝트 화면 위, 또는 사이드바 프로젝트 우클릭)는 AgentHub 목록에서 프로젝트를 뺀다. 이 프로젝트의 AgentHub 세션·연결·공유 노트는 지우지만, 프로젝트 폴더와 파일, Claude Code·Codex 기록은 건드리지 않는다. 같은 폴더를 다시 추가하면 다시 보인다.

## 사용 한도

대시보드의 **사용 한도**와 사이드바 아래에 남은 비율과 초기화 시각이 나온다. Claude는 5시간 한도를 늘 함께 보여 준다. 두 CLI 모두 남은 한도를 묻는 공개 명령이 없으므로, CLI가 마지막으로 알려 준 값을 보여 준다. Claude는 AgentHub에서 한 번도 실행하지 않았으면 비어 있을 수 있다.

## 권한 모드

| AI | 모드 | 의미 |
| --- | --- | --- |
| Claude | `plan` | 읽기와 계획만 한다. |
| Claude | `acceptEdits` (기본) | 파일 수정은 허용하고, 허용되지 않은 명령은 거부된다. |
| Claude | `bypassPermissions` | 모든 도구를 확인 없이 실행한다. 프로젝트 원본 폴더에도 적용된다. |
| Codex | `read-only` | 읽기만 한다. |
| Codex | `workspace-write` (기본) | 작업 폴더 안의 쓰기를 허용한다. |
| Codex | `auto-review` | 작업 폴더 안의 쓰기를 허용하고, 추가 승인은 검토 AI가 판단한다. |
| Codex | `danger-full-access` | 샌드박스와 실행 승인 절차를 해제해 전체 접근을 허용한다. |

AI가 허용되지 않은 일을 하려 하면 세션 화면에 **권한 요청** 카드가 뜬다. **허용**·**거절** 중에 고르고, 제안이 있으면 **항상 허용**이나 **이번 실행에서 허용**으로 같은 요청을 다시 묻지 않게 할 수 있다.

## 업데이트

설치형 앱은 시작 5초 뒤, 이후 1시간마다, 그리고 사이드바 아래 **업데이트 확인**을 누를 때 새 버전을 확인한다. 새 버전은 백그라운드에서 받고, **재시작해서 업데이트**를 누르면 설치 창 없이 설치한 뒤 다시 실행한다. 받아 둔 업데이트는 앱을 닫을 때도 조용히 설치된다.

포터블 버전은 자기 자신을 바꿀 수 없어서 릴리스 페이지를 연다. 0.1.12 이하를 쓰고 있다면 0.1.13 이후 설치 파일을 한 번 직접 설치해야 한다.

## 알려진 한계

- 원본 폴더에서 일하는 세션끼리 같은 파일을 동시에 고치면 서로의 수정을 덮을 수 있다. 같은 파일을 고칠 세션은 워크트리로 나누거나 동시에 실행하지 않는다.
- 여러 세션이 같은 Unity Editor를 동시에 쓰지 않도록 하는 잠금은 아직 없다.
- 이미지 처리와 승인 요청의 종류는 설치한 CLI와 선택한 모델이 지원하는 범위를 따른다.
- 이 앱은 AI에게 파일 수정과 명령 실행을 맡기므로 이 PC 안(`127.0.0.1`)에서만 열린다.
