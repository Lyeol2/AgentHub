# 릴리스 준비

AgentHub 릴리스(`npm run release`)를 돌려도 되는지 점검한다. **릴리스 자체는 직접 실행하지 않는다.** 실제 릴리스는 흐름의 명령 노드가 사람의 승인을 받은 뒤 실행한다.

이 스킬은 점검만 한다. 파일을 고치거나 커밋하지 않는다. 하나라도 걸리면 바로 실패로 끝낸다.

## 순서
1. `git status --porcelain`을 본다. 출력이 하나라도 있으면(수정·추가·삭제·추적 안 된 파일 모두) **실패**다.
   - 커밋하지 않는다. 남은 파일 목록을 그대로 보여 주고, 먼저 커밋해야 한다고 알린 뒤 끝낸다.
2. `git log --oneline`으로 지난 릴리스(`chore: release vX.Y.Z`) 이후 커밋을 파악한다. 커밋이 없으면 릴리스할 것이 없으므로 **실패**다.
3. `npm test`를 돌린다. 실패하면 고치지 않고 실패한 테스트와 출력을 보고하고 **실패**로 끝낸다.
4. README처럼 기능을 설명하는 문서가 지난 릴리스 이후 바뀐 기능과 어긋나는지 본다. 어긋나면 고치지 않고 어디가 어떻게 다른지 보고하고 **실패**로 끝낸다.
5. 버전 단위를 판단해 답변에 적는다. 기본은 patch, 새 기능이 크면 minor, 호환이 깨지면 major.
   - patch가 아니면 "릴리스 명령을 `npm run release -- minor`로 바꿔야 한다"고 분명히 알린다.
6. 하지 않는 것: 파일 수정, `git add`, `git commit`, `git stash`, `npm run release`, `npm version`, `git push`, `git tag`, `gh release`.
7. 모두 통과했으면 지난 릴리스 이후 바뀐 점 요약과 추천 버전 단위를 쓰고, **마지막 줄에 정확히 "릴리스 준비"**라고 쓴다.
   - 실패했으면 이 말을 쓰지 않는다. 대신 실패한 단계와 이유를 쓴다.

## 릴리스가 실패해서 돌아왔을 때
- 출력을 보고 원인을 진단해 보고한다. 직접 고치거나 다시 릴리스하지 않는다.
- 버전만 올라가고 커밋이 안 된 상태(`package.json` 변경)인지, 커밋·태그까지 된 상태인지 확인해 알린다.
