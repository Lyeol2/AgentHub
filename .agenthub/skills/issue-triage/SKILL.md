# 이슈 분석

이 노드는 수정 전에 현상과 기대 동작을 구분하고, 다음 노드가 바로 확인할 수 있는 근거를 만든다. 프로젝트 파일은 수정하지 않는다.

- 사용자 이슈 번호·링크가 있으면 그대로 이슈 키로 쓴다. 없으면 현재 실행을 구별할 짧은 요약과 시각을 정한다. 새 이슈의 수정 회차는 0/3이다. 이전 이슈의 회차를 이어 쓰지 않는다.
- 프로젝트 지침, 관련 구현, 기존 테스트와 현재 변경 상태를 읽는다. 재현 절차와 실제 관찰을 기록하고 확인한 원인과 추측을 구분한다. 읽기 전용으로 실행할 수 없는 재현은 수정 노드에 구체적인 명령과 기대 결과를 넘긴다.
- 해당 현상을 설명하는 원인과 고칠 범위, 수정 후 확인할 기준을 정한다. 환경·권한·접속 실패를 제품 버그로 단정하지 않는다. 정보가 일부 부족해도 안전하게 확인할 수 있으면 진행한다.
- 결정적인 재현 정보나 사용자 결정 없이는 진행할 수 없으면 부족한 정보와 이유를 남겨 결과 정리 노드로 보낸다. 분석 단계에서 같은 질문을 별도로 발송하지 않는다.

## 인계

답변은 6,000자 이내로 유지한다. 이슈 키, 사용자 원래 요청과 기대 동작, 재현 절차·관찰, 근거 파일/위치, 수정 범위, 검증 기준, 기존 변경/미확인 사항, 수정 회차 0/3을 포함한다. 이후 노드에는 이 답변만 전달되어도 이슈를 이해할 수 있어야 한다.

마지막 줄에는 판정 하나만 쓴다. 수정할 가설·범위와 확인 방법을 확보했으면 "수정 준비", 진행에 필수인 정보·결정이 없으면 "진행 보류".
