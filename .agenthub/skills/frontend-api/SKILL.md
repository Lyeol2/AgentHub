# 화면에서 서버와 주고받기

화면과 서버의 약속(경로 모양, 응답·오류 형식, `reason`, 필드 이름, 이벤트 이름과 실을 데이터)은 **`backend` 스킬의 "프론트엔드와 맞물리는 부분"을 기준으로 삼는다.** 여기서 같은 내용을 다시 적지 않는다. 약속을 바꿔야 하면 서버와 화면을 한 번에 고치고, 그 스킬도 고친다.

## 요청
- 서버 호출은 `api(method, url, body)`만 쓴다. `fetch`를 직접 부르거나 헤더를 따로 만들지 않는다(`X-AgentHub` 헤더가 빠지면 403).
- 데이터를 바꾸는 요청은 GET으로 보내지 않는다.
- 만들기·고치기 응답은 바뀐 객체 전체이므로, 요청한 창은 그 응답으로 `state`를 고치거나 해당 `load…()`를 부른다. `{ ok: true }`만 오는 요청은 `load…()`로 다시 받는다.
- 버튼을 누른 동안 같은 요청이 두 번 가지 않게 한다(실행 중에는 `disabled`). 오래 걸리는 요청은 진행 중임을 보여 준다.

## 오류
- `api()`는 실패하면 `err.message`(서버의 한국어 `error`)와 `err.reason`을 담아 던진다.
- 대화상자에서는 `…-error` 칸에 `err.message`를 보여 주고 대화상자를 닫지 않는다. 대화상자 밖에서는 `alert(err.message)`.
- 다음 선택지를 물어야 하는 실패만 `err.reason`으로 가른다(예: 세션 삭제의 `"running"` → `confirm` 후 `?force=1`로 다시 요청). 상태 코드로 가르지 않는다. 서버에 새 `reason`이 생기면 여기서 처리하는 곳을 만든다.
- 화면에 오류 문구를 따로 지어내지 않는다. 서버 메시지가 어색하면 서버 쪽을 고친다.

## 실시간 이벤트
- `/api/stream`은 `connectStream()`의 `EventSource` 하나만 연다. 기능마다 연결을 새로 만들지 않는다.
- 이벤트가 오면 대부분 그 자원을 다시 받는다(`sessions` → `loadSessions()`). 범위가 실려 오면 지금 보는 화면과 맞을 때만 다시 받는다(`samePath(data.projectPath, state.project)`, `data.sessionId === state.current?.id`).
- `event`는 `event.seq`로 이미 받은 것을 건너뛴다. 새 처리기도 같은 이벤트가 두 번 와도 화면이 깨지지 않게 만든다.
- 연결이 다시 열리면(`open`) 목록과 보던 세션을 다시 받는다. 새 화면 상태도 이때 다시 받아야 하면 여기에 넣는다.
- 별도 창(`POPUP`)에서도 처리기가 돈다. 그 창에 없는 요소(사이드바 등)를 건드리기 전에 확인한다.
- 새 이벤트 이름을 받으려면 서버의 `broadcast`와 `connectStream()`의 처리기를 함께 만든다.

## 순서
1. `app.js`에서 해당 경로(`/api/...`)와 이벤트 이름을 `grep`으로 찾아 지금 화면이 무엇을 기대하는지 본다. 서버 쪽은 `handleApi`의 그 경로를 읽는다.
2. 서버를 고쳐야 하면 `backend` 스킬을, 화면 모양은 `frontend` 스킬을 따른다.
3. `npm test`를 돌린다. 그다음 `npm start`로 띄워 창 두 개를 열고, 한쪽에서 바꾼 것이 다른 쪽에도 반영되는지, 실패할 때 메시지가 제대로 나오는지 확인한다. 직접 확인하지 못했으면 그렇다고 알린다.
4. 하지 않는 것: 보안 헤더 우회, 새 패키지 추가, 릴리스.
