# 기능 문서: 저장소 화면 (Fork·SourceTree 같은 git 클라이언트)

- 상태: 초안 (2026-10-15). 프로젝트 화면의 **Git** 탭(변경 파일 커밋, 브랜치, 최근 커밋, 세션 브랜치 병합)이 먼저 들어갔다. 이 문서는 그 다음 단계(그래프, 덩어리 스테이지, 원격, 충돌 해결)의 기준이다.
- 범위: 서버 `server/git.mjs`·`server/gitgraph.mjs`(새로) · `server/index.mjs`의 `/api/git` 경로 · 화면 `public/`의 저장소 화면

## 1. 왜 만드는가

AgentHub 세션은 **별도 작업 폴더**를 켜면 `<저장소>.agenthub/<세션 ID>`에 worktree와 `agenthub/<세션 ID>` 브랜치를 만든다. 세션이 여럿 돌면 브랜치도 여럿 생기는데, 지금 AgentHub에서 볼 수 있는 git 정보는 세션 화면의 **변경 보기**(기준 커밋과의 diff) 하나뿐이다. 결과를 확인하고 합치려면 Fork·SourceTree·터미널을 따로 열어야 한다.

저장소 화면은 이 빈틈을 메운다.

1. 프로젝트의 커밋 그래프에서 **세션 브랜치가 어디서 갈라져 어디까지 왔는지** 한눈에 본다.
2. 세션이 만든 변경을 파일·덩어리(hunk) 단위로 보고, 골라서 커밋하고, 원래 브랜치로 합친다.
3. 일반 git 클라이언트의 기본 기능(스테이징, 커밋, 브랜치, fetch·pull·push, stash, 충돌 해결)을 앱을 떠나지 않고 쓴다.

Fork·SourceTree를 통째로 대신하는 것이 목표가 아니다. **에이전트가 만든 브랜치를 검토하고 합치는 흐름**을 먼저 완성하고, 일반 클라이언트 기능은 그 흐름에 필요한 만큼부터 넣는다.

## 2. 하지 않는 것 (이번 범위 밖)

- 대화형 rebase 편집기(커밋 순서 바꾸기·squash·reword를 끌어서 하는 화면). 4단계 이후에 따로 검토한다.
- git LFS 관리, 서브모듈 갱신·편집(표시만 한다), GPG 서명 설정, git 설정(`git config`) 편집기.
- GitHub·GitLab PR 만들기·리뷰. 이미 있는 GitHub CLI 연동으로 나중에 붙일 수 있다.
- 원격 저장소 추가·삭제·URL 변경. 처음에는 기존 원격만 쓴다.
- 자격 증명 저장. 사용자 PC의 git credential manager에 맡긴다.

## 3. 용어

| 용어 | 뜻 |
| --- | --- |
| 저장소 | AgentHub 프로젝트 폴더의 git 저장소(원본). |
| 작업 폴더 | 원본 또는 세션의 worktree. git 명령은 항상 어떤 작업 폴더를 기준으로 실행한다. |
| 세션 브랜치 | `agenthub/<세션 ID>`. 화면에서는 세션 이름으로 보여 준다. |
| 대상 브랜치 | 세션 브랜치를 합칠 곳. 기본은 세션을 만들 때 원본이 있던 브랜치. |

## 4. 화면

### 4.1 들어가는 곳

- 프로젝트 화면 위에 **저장소** 탭(또는 버튼). 프로젝트가 git 저장소가 아니면 숨긴다.
- 세션 화면의 **변경 보기** 옆에 **저장소에서 보기**: 저장소 화면을 열고 그 세션의 작업 폴더·브랜치를 고른 상태로 시작한다.
- 별도 창 `?repo=<프로젝트 경로>`로도 연다(사이드바 없음). Fork처럼 큰 창으로 따로 띄워 쓰기 위해서다.

### 4.2 배치

Fork의 3단 배치를 따른다.

```
┌──────────────┬───────────────────────────────────────────────┐
│ 작업 폴더 ▾   │ [Fetch] [Pull] [Push] [브랜치] [Stash] [새로고침] │
│──────────────│───────────────────────────────────────────────│
│ ● 로컬 변경 3 │  그래프 │ 메시지              │ 작성자 │ 날짜  │
│ 브랜치        │  ●─┐    │ feat: …  [main]     │        │       │
│   main        │  │ ●    │ wip  [세션: 리뷰]    │        │       │
│   ▸ 세션 (4)  │  ●─┘    │ …                   │        │       │
│ 원격          │─────────────────────────────────────────────── │
│ 태그          │ 커밋 정보 / 바뀐 파일 목록 │ 파일 diff           │
│ Stash         │                            │                    │
│ 작업 폴더     │                            │                    │
└──────────────┴───────────────────────────────────────────────┘
```

- **왼쪽 사이드바**: 작업 폴더 고르기, 로컬 변경(개수), 로컬 브랜치, **세션 브랜치 묶음**(세션 이름·상태 점·AI 색), 원격 브랜치, 태그, stash, worktree 목록.
- **가운데 위**: 커밋 그래프 + 목록. 브랜치·태그·HEAD 표시를 커밋 줄에 칩으로 붙이고, 세션 브랜치 칩은 `--claude`/`--codex` 색을 쓴다.
- **가운데 아래**: 고른 커밋의 정보(해시, 부모, 작성자, 메시지)와 바뀐 파일 목록, 오른쪽에 파일 diff.
- 좁은 화면(`max-width: 900px`)에서는 사이드바를 접고, 아래 칸을 위아래로 쌓는다.

### 4.3 로컬 변경 화면

사이드바의 **로컬 변경**을 누르면 가운데가 바뀐다.

- 왼쪽 위 **스테이지 안 됨**, 왼쪽 아래 **스테이지됨** 파일 목록. 파일마다 상태(M/A/D/R/?/U)와 경로.
- 파일을 두 번 누르거나 끌어서 스테이지·언스테이지. 여러 개 골라 한 번에. **모두 스테이지** 버튼.
- 오른쪽 diff에서 덩어리마다 **덩어리 스테이지 / 언스테이지 / 버리기**. 줄을 골라 **선택한 줄만 스테이지**(3단계).
- 아래 커밋 칸: 제목·본문, **마지막 커밋 고치기(amend)** 체크, **커밋**·**커밋하고 Push** 버튼. 저장소의 커밋 형식(`feat:`/`fix:`/`chore:`)은 강제하지 않는다.
- **AI에게 커밋 메시지 맡기기**(5단계): 스테이지된 diff 요약을 고른 세션에 보내 메시지를 받아 칸에 채운다.

### 4.4 diff 보기

- 기존 `renderDiff`를 넓혀 쓴다. 한 칸(unified) 기본, **나란히 보기**는 2단계.
- 공백 무시, 맥락 줄 수(3/10/전체) 고르기.
- 큰 파일은 5,000줄에서 자르고 **전부 보기**를 보여 준다. 바이너리는 "바이너리 파일"과 크기만 보여 주고, 이미지(png/jpg/gif/svg)는 전후 그림을 띄운다(3단계).

### 4.5 세션과 이어지는 부분 (AgentHub만의 기능)

- 세션 브랜치 오른쪽 클릭 메뉴:
  - **세션 열기**, **대상 브랜치와 비교**(`대상...세션` 차이)
  - **대상 브랜치로 합치기**: merge(기본, `--no-ff`) / squash merge / rebase 후 fast-forward 중에 고른다.
  - **이 세션 작업 폴더로 전환**(작업 폴더 고르기를 바꾼다)
  - **브랜치 지우기**: 세션이 남아 있으면 막고, 세션 삭제를 권한다.
- 세션이 **실행 중**인 작업 폴더에서는 쓰기 명령(스테이지, 커밋, checkout, merge, reset, stash)을 막는다. 화면에 "세션이 실행 중입니다. 일시중지하거나 끝난 뒤 하세요"를 띄운다. 읽기(그래프, diff)는 언제든 된다.
- 합치기에서 충돌이 나면 충돌 화면(4.7)에 **세션에게 충돌 해결 맡기기**를 둔다. 충돌 파일 목록과 대상·세션 브랜치를 요청으로 만들어 그 세션(또는 고른 세션)에 보낸다. 세션은 대상 브랜치를 자기 작업 폴더로 합치고 해결해 커밋한다. 원본 폴더의 충돌 상태는 **합치기 취소**로 되돌린다.
- 세션 턴이 끝나면(`turnEnd`) 그 세션 작업 폴더의 저장소 화면을 새로 고친다.

### 4.6 브랜치·원격·stash

| 기능 | 단계 | 비고 |
| --- | --- | --- |
| 브랜치 만들기(고른 커밋에서), 이름 바꾸기, checkout | 2 | 변경이 있으면 checkout 전에 stash할지 묻는다. |
| 브랜치 지우기 | 2 | 합치지 않은 브랜치는 `-D` 확인을 한 번 더 받는다. |
| Fetch(전체 원격, `--prune`) | 3 | 앱이 켜져 있는 동안 자동 fetch는 설정으로 켠다(기본 끔). |
| Pull | 3 | 기본 `--ff-only`. 실패하면 merge·rebase 중에 고르게 한다. |
| Push | 3 | upstream이 없으면 `-u origin <브랜치>`로 만들지 묻는다. 강제 push는 `--force-with-lease`만 쓴다. |
| Stash 저장·적용·꺼내기·지우기 | 2 | 아래 주의 참고. |
| 태그 만들기·지우기·push | 4 | |
| Cherry-pick, Revert, Reset(soft/mixed/hard) | 4 | hard는 확인을 받고, 지울 변경 개수를 보여 준다. |

**stash 주의**: stash 목록은 원본과 모든 worktree가 함께 쓴다. 세션 에이전트도 같은 목록을 쓸 수 있다. 그래서

- AgentHub가 만드는 stash는 메시지에 `agenthub:<작업 폴더 이름>:<시각>` 표시를 붙인다.
- 적용·지우기는 `stash@{n}`이 아니라 **커밋 해시**로 고른다. 실행 직전에 목록을 다시 읽어 그 해시의 현재 위치를 찾는다.
- 목록에는 모든 stash를 보여 주되, 다른 작업 폴더에서 만든 것은 흐리게 표시한다.

### 4.7 충돌 해결

- 합치기·pull·rebase·cherry-pick·stash 적용 중 충돌이 나면 저장소 화면 위에 **충돌 띠**: 진행 중인 작업 이름, 충돌 파일 수, **계속**·**취소**(`--abort`).
- 충돌 파일을 고르면 세 칸(내 것 / 결과 / 받은 것). 덩어리마다 **내 것 / 받은 것 / 둘 다** 고르고, 결과 칸은 직접 고칠 수 있다(4단계). 그 전 단계에서는 **내 것으로 / 받은 것으로**(`checkout --ours/--theirs`)와 **외부 편집기로 열기**만 둔다.
- 모든 충돌이 풀리면 **해결로 표시**(`git add`) 후 **계속**.

### 4.8 그 밖의 보기 (5단계)

- 파일 기록(`log --follow`), blame(줄마다 커밋·작성자, 세션 브랜치 커밋이면 세션 이름).
- 커밋·메시지·작성자·경로로 찾기(`log --grep`/`--author`/`-- <경로>`).
- 두 커밋·브랜치 비교.

## 5. 서버 설계

### 5.1 모듈

- `server/git.mjs`: 기존 `git()`을 그대로 쓰고, 명령별 함수를 더한다(`status`, `log`, `show`, `stage`, `commit` …). 출력은 사람이 읽는 형식이 아니라 기계용 형식으로 받는다.
  - status: `status --porcelain=v2 -z --branch --untracked-files=all`
  - log: `log --topo-order -z --format=<%H %P %an %ae %at %s ...> --decorate=full` (필드 구분은 `%x1f`, 줄 구분은 `-z`)
  - 브랜치·태그: `for-each-ref --format=...`
- `server/gitgraph.mjs` (새로): 커밋 목록(해시·부모)을 받아 그래프 줄(lane) 배치를 계산하는 **순수 함수**. 화면은 결과대로 그리기만 한다. 페이지를 나눠 받아도 이어지도록 이전 페이지 끝의 lane 상태를 함께 받는다.
- `server/gitops.mjs` (필요하면): merge·rebase·충돌처럼 여러 단계를 거치는 동작과 "실행 중 세션의 작업 폴더인지" 검사.

### 5.2 API

모두 `/api/git` 아래. 작업 폴더는 쿼리·본문의 `cwd`로 받고, **등록된 프로젝트 폴더나 그 프로젝트 세션의 worktree 폴더인지** 서버가 확인한다(아니면 400). 읽기는 GET, 바꾸기는 POST.

| 경로 | 하는 일 |
| --- | --- |
| `GET /api/git/state?cwd=` | HEAD, 현재 브랜치, upstream과 앞섬·뒤처짐, 진행 중 작업(merge/rebase/cherry-pick), 충돌 파일 수, 로컬 변경 수 |
| `GET /api/git/refs?cwd=` | 로컬·원격 브랜치, 태그, stash, worktree. 세션 브랜치에는 `sessionId`·`title`·`agent`·`running`을 붙인다. |
| `GET /api/git/log?cwd=&ref=&skip=&limit=` | 커밋 목록 + 그래프 배치. 기본 `--all`, 한 번에 300개. |
| `GET /api/git/commit/:hash?cwd=` | 커밋 정보와 바뀐 파일 목록 |
| `GET /api/git/diff?cwd=&kind=&path=&from=&to=` | 파일 diff. `kind`는 `unstaged`·`staged`·`commit`·`range` |
| `GET /api/git/status?cwd=` | 스테이지 안 됨·스테이지됨·충돌 파일 목록 |
| `POST /api/git/stage` · `unstage` · `discard` | `{ cwd, paths }` 또는 `{ cwd, path, patch }`(덩어리·줄 단위는 화면이 만든 패치를 `apply --cached`) |
| `POST /api/git/commit` | `{ cwd, message, amend }` |
| `POST /api/git/branch` | `{ cwd, action: create\|rename\|delete\|checkout, ... }` |
| `POST /api/git/fetch` · `pull` · `push` | 원격 동작. 오래 걸리므로 4.9의 작업 진행 방식으로 돌린다. |
| `POST /api/git/merge` | `{ cwd, from, mode: merge\|squash\|rebase }`. 세션 브랜치 합치기도 이 경로를 쓴다. |
| `POST /api/git/stash` | `{ cwd, action: save\|apply\|pop\|drop, hash?, message? }` |
| `POST /api/git/conflict` | `{ cwd, action: ours\|theirs\|resolve\|continue\|abort, path? }` |
| `POST /api/git/handoff` | 충돌 해결을 세션에 맡긴다. `{ cwd, sessionId }` |

- 실패는 기존 관례대로 `HttpError(상태, "한국어 메시지", reason)`. 화면이 다음 선택지를 물어야 하는 경우의 `reason`:
  - `running`: 실행 중인 세션의 작업 폴더라 쓰기를 막았다.
  - `dirty`: 변경이 있어 checkout·pull을 못 했다 → stash하고 다시 할지 묻는다.
  - `conflict`: 충돌이 났다 → 충돌 화면을 연다.
  - `nonFastForward`: pull·push가 fast-forward가 아니다 → merge/rebase 또는 `--force-with-lease`를 묻는다.
  - `unmerged`: 합치지 않은 브랜치 삭제 → `-D`로 지울지 묻는다.
  - `locked`: `index.lock`이 있다(다른 git이나 에이전트가 쓰는 중) → 잠시 뒤 다시 하라고 알린다. 잠금 파일을 지워 주지 않는다.

### 5.3 실시간 알림

- 새 SSE 이벤트 `git` `{ cwd }`: 이 서버가 그 작업 폴더에 쓰기 명령을 했을 때, 세션 턴이 끝났을 때 보낸다. 화면은 보고 있는 작업 폴더면 `state`·`refs`·`log` 첫 페이지를 다시 받는다.
- 앱 밖(터미널, Fork, 에이전트의 git 명령)에서 바뀐 것은 창이 다시 포커스를 받을 때와 **새로고침** 버튼으로 반영한다. `.git` 폴더 감시(`fs.watch`)는 Windows에서 이벤트가 많고 worktree마다 위치가 달라 처음에는 하지 않는다.
- `app.js`의 `connectStream`에 `git` 처리기를 넣는다(`backend` 스킬의 SSE 약속).

### 5.4 동시에 실행되는 git 막기

- 같은 저장소(원본과 그 worktree들이 함께 쓰는 `.git`)에 대한 쓰기 명령은 서버 안에서 **저장소별 대기열**로 하나씩 실행한다.
- 세션이 실행 중인 작업 폴더의 쓰기는 409 `running`. 원본 폴더에서 도는 세션(별도 작업 폴더를 끈 세션)도 같다.
- 에이전트가 그 사이에 git을 쓰는 것은 막을 수 없으므로 `index.lock` 오류를 `locked`로 바꿔 알린다.

### 5.5 오래 걸리는 명령 (fetch·pull·push)

- 바로 `{ jobId }`를 돌려주고, 진행 출력은 SSE `git` `{ cwd, jobId, line }` 또는 끝났을 때 `{ cwd, jobId, done, error }`로 보낸다. 화면은 저장소 화면 아래 작은 진행 칸에 보여 준다.
- 터미널 입력을 기다리며 멈추지 않도록 `GIT_TERMINAL_PROMPT=0`을 주고 stdin을 닫는다. credential manager의 로그인 창은 막지 않는다(처음 push할 때 그 창이 떠야 한다). 120초가 넘으면 끊는다.
- 인증 실패는 "GitHub 로그인이 필요합니다. 설정 → CLI 경로에서 GitHub CLI 로그인을 하거나 git credential manager로 로그인하세요."처럼 알린다.

### 5.6 보안

- 사용자 입력을 셸에 넣지 않는다. `execFile`로 인자 배열만 넘긴다(지금 `git()`과 같다).
- 브랜치·태그 이름은 `git check-ref-format --branch`로 검사한다. `-`로 시작하는 값은 받지 않는다.
- 경로 인자는 항상 `--` 뒤에 넣고, 작업 폴더 안의 상대 경로인지 정규화해서 확인한다.
- 커밋 해시는 `^[0-9a-f]{7,40}$`만 받는다.
- 덩어리 스테이지용 패치는 1MB(기존 `readJson` 한도) 안에서 받고, `git apply --cached --check`로 먼저 확인한다.
- `cwd`는 5.2의 허용 폴더만. 임의 폴더의 git을 다루지 못하게 한다.
- 커밋 메시지는 `-F -`(stdin)로 넘긴다.

### 5.7 성능

- 로그는 300개씩 나눠 받고, 화면은 보이는 줄만 그린다(가상 스크롤). 커밋 1만 개 저장소에서 첫 화면 1초 안이 목표.
- `refs`·`state`는 가볍게 유지하고, diff는 파일 하나씩 받는다.
- 세션 브랜치 묶음은 브랜치 이름이 `agenthub/`로 시작하는 것을 `store`의 세션과 맞춰 만든다. 세션이 지워진 세션 브랜치는 "남은 세션 브랜치"로 따로 모아 정리할 수 있게 한다.

## 6. 단계

| 단계 | 내용 | 끝났다고 보는 기준 |
| --- | --- | --- |
| 1. 읽기 | 저장소 화면, 사이드바(브랜치·세션 브랜치·원격·태그·stash·worktree), 커밋 그래프, 커밋 정보·파일 diff, 로컬 변경 목록(읽기만) | 세션 3개가 각자 커밋한 저장소에서 세 브랜치가 그래프에 갈라져 보이고, 세션 이름 칩으로 구분된다. |
| 2. 로컬 쓰기 | 파일·덩어리 스테이지, 버리기, 커밋·amend, 브랜치 만들기·바꾸기·지우기·checkout, stash, 나란히 diff, 실행 중 세션 잠금 | 저장소 화면만으로 세션 변경 일부를 골라 커밋할 수 있다. |
| 3. 원격 | fetch·pull·push, 진행 출력, upstream 만들기, 줄 단위 스테이지, 이미지 diff | 새 브랜치를 처음 push하고 pull 충돌 없는 경우를 끝낼 수 있다. |
| 4. 합치기 | 세션 브랜치 합치기(merge/squash/rebase), 충돌 화면(세 칸 편집 포함), 세션에게 충돌 맡기기, cherry-pick·revert·reset·태그 | 세션 브랜치를 대상 브랜치로 합치고, 충돌이 나면 세션에게 넘겨 해결된 결과로 다시 합칠 수 있다. |
| 5. 더 보기 | 파일 기록, blame, 찾기, 비교, AI 커밋 메시지 | |

각 단계는 따로 릴리스할 수 있게 나눈다. 1단계만으로도 "세션 브랜치를 한눈에 보기"라는 쓸모가 있다.

## 8. 정할 것

1. 들어가는 곳: 프로젝트 화면의 탭으로 둘지, 사이드바에 프로젝트마다 **저장소** 항목을 둘지.
2. 세션 브랜치 합치기의 기본 방식: `--no-ff` merge(세션 단위 기록이 남음) vs squash(대상 브랜치가 깔끔함).
3. 합친 뒤 세션 브랜치·작업 폴더를 자동으로 지울지(기본은 묻기).
4. 자동 fetch를 넣을지, 넣으면 기본 간격.
5. 원본 폴더에서 도는 세션이 있을 때 원본 폴더 쓰기를 모두 막을지, 경고만 할지.
