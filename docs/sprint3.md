# 스프린트3: 워크트리 생명주기 안정화

## 목표

작업 워크트리의 **생성 → 작업 → 마무리 → 정리** 전 과정을 믿을 수 있게 만들고, 사용자가 지금 어느 폴더·브랜치에서 일하는지와 왜 막혔는지를 한눈에 보게 한다.

- 범위: 워크트리 생성·선택, 정리·삭제, 병합 충돌·중단 복구, 화면 표시.
- 제외: 노드 추가(다음 스프린트), 새 워크트리의 의존성 자동 설치, 저장소의 긴 경로 설정, 오프라인 작업 생성, 오케스트레이터 계획의 부분 적용 되돌리기.
- 결정: 병합을 확인한 뒤 정리는 자동으로 하지 않고 카드에서 제안하며, 확인 창을 거쳐 실행한다.

## 시작할 때 확인한 문제(실제 저장소)

| 남은 워크트리 | 원인 | 해결 항목 |
| --- | --- | --- |
| PR #13·#15 작업 폴더 | GitHub에서 병합했지만 작업 기록이 "검토 대기"에 머물러 정리 버튼이 나오지 않음 | A1 |
| 폴더가 사라진 이전 작업 2개 | 정리가 먼저 폴더를 요구해 영원히 실패, 브랜치만 남음 | A2 |
| `work-<hash>`(main) | 로컬 반영용 임시 폴더를 지우지 않아 원본에서 `checkout main`이 막힘 | A5 |
| `agenthub-release-*`(임시) | 릴리스 스크립트가 지우지 못하고 prune도 하지 않음 | A4 |

## 남은 위험

- 세션 프로세스 종료를 기다리지 않고 삭제를 재시도(약 10초)로 덮는다. CLI가 남긴 개발 서버가 오래 폴더를 잡으면 "폴더 남음"으로 끝날 수 있다.
- 흐름의 Git 노드(로컬 병합)가 만든 대상 작업 폴더는 다음 노드가 이어 쓸 수 있어 그대로 둔다. Git 탭의 작업 폴더 목록에서 정리한다.
